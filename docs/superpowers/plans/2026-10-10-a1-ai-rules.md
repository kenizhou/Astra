# A1 AI Rules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the judge primitive with safe defaults, the rules engine (generation, matching, deterministic execution, CLI CRUD), categorisation, the cold blocker, active DLP, the eval harness with pipeline constants, the nano spend guard, and the live gated suite against the provided endpoint.

**Architecture:** The judge and DLP live on the Rust client path (astra-ai + client/desktop); rules and their execution live in astra-app over the product store; the incoming pass hooks refresh; the CLI grows rules verbs; evals run as gated cargo tests.

**Tech Stack:** Existing workspace; the provided DeepSeek anthropic endpoint for the live gate (tier 3).

**Spec:** `docs/superpowers/specs/2026-10-10-a1-ai-rules-design.md` + `docs/superpowers/specs/2026-10-10-binary-judge-design.md`

## Global Constraints

- House rules as every slice: SPDX, 500-line cap, deny-everything lints, gate before commit (direct exit), conventional commits, no dashes, British English, zh mirrors same-commit, additive wire only.
- The provided connection (never committed; the live gate reads it from env): `ASTRA_LLM_DEFAULT/ECONOMY/CHAT=anthropic:deepseek-flash`, `ASTRA_LLM_API_KEY_ANTHROPIC=<key>`, `ASTRA_LLM_BASE_URL_ANTHROPIC=https://api.deepseek.com/anthropic`.
- Security floor: judges gate UX only; the permission bridge and send refusal untouched; mail content in prompts always wrapped; DLP block is fail-closed.
