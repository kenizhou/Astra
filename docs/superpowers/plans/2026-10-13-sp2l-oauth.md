# SP2l OAuth Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the OAuth foundation: the pure PKCE client crate, the system-browser session with the deep-link redirect, the credential transaction with its three answer paths, the wizard's OAuth skeleton with the refusal states, the discovery live proof, and the contract doc.

**Architecture:** `astra-oauth` (new crate, ported from mail-calendar's `mailcal-oauth`: pure, testable, no engine dependency) owns the flow's pure half; the desktop host owns the browser session and the OS keystore; the app core owns the transaction's "when".
**Tech Stack:** Existing workspace plus `astra-oauth` (sha2/rand or whatever MC's crate pins for S256 and state; port the same choices); `tauri-plugin-deep-link` (already a dependency).
**Spec:** `docs/superpowers/specs/2026-10-13-sp2l-oauth-design.md`

## Global Constraints

- House rules as every slice: SPDX, 500-line cap, deny-everything lints, gate before commit (direct exit), conventional commits, no dashes, British English, zh mirrors same-commit, additive wire only.
- Standing: AUTO-CONTINUE the moment the PR merges; SQUASH AND MERGE; the 10-minute author window.
- The engine is OAuth-agnostic (bearer token in, nothing more); no OAuth code leaks into it. Tokens never touch a log; Debug redaction everywhere.
