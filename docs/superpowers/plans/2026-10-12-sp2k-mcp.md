# SP2k MCP Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the MCP server end to end: the query layer with its two-door split, the tool surface with the body rules and the ledger, the named-pipe listener with the peer check, the stdio relay binary, the Advanced settings panel with the account allowlist, the e2e and live proofs, and the contract doc with the two recorded deviations.

**Architecture:** astra-app owns the query layer (reads that change nothing) beside the existing dispatch (writes); a new astra-mcp crate owns the server, the tool schemas, and the JSON-RPC framing; a relay binary bridges stdio to the pipe; the desktop host runs the listener and the Advanced panel gates it.
**Tech Stack:** Existing workspace plus the named-pipe/socket transport (std/interprocess as the survey decides); no protocol dependency (the JSON-RPC framing is hand-rolled and vector-pinned, the relay knows no protocol).
**Spec:** `docs/superpowers/specs/2026-10-12-sp2k-mcp-design.md`
