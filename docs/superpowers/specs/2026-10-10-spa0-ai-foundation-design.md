# SPA0 AI Foundation Design

Date: 2026-10-10
Status: proposed
Parent spec: `docs/superpowers/specs/2026-10-08-astra-ai-driven-workflow-design.md` (sections 7, 8, 9, 15)
Discharges: the product-database arrival recorded in the SP1 spec (D4): the AI ledgers need it now.

## 1. Purpose

Stand the AI skeleton upright and prove it with one real conversation: the
Node sidecar (light, secure, fully traceable), the tier and use-case
registry with the per-call ledger, the background dual-protocol LLM client,
the astra-cli agent tool surface with the audit log, and a minimal agent
panel in the shell. A1 to A4 features grow inside these seams.

## 2. Decisions

- **D1 (astra-ai crate)**: `crates/astra-ai` owns the registry and the
  ledgers: `LlmUseCase` (starter set grown with each AI slice; SPA0 ships
  AssistantChat, DraftReply, Summarise, CategorizeSender, CleanInbox,
  AgentTool), `ModelTier` (Default, Economy, Chat, Draft, Nano), the tier
  table (env-configurable comma lists, inbox-zero syntax: first entry
  primary, rest fallback), the product SQLite store (sqlx; migrations in
  the crate: `llm_calls` and `audit_log` tables; opened by the host and
  the CLI against the same data dir), the `CorrelationId` newtype, and the
  prompt-injection hardening wrapper (an untrusted-content tag function
  with the DLP policy enum; allow is the default policy, redact and block
  arrive with A1's features, recorded).
- **D2 (background LLM client)**: a dual-protocol client
  (`openai-completions` and `anthropic-messages` wire shapes) in
  `client/desktop`, driven by the registry: tier fallback on retryable or
  quota errors, JSON-repair for structured outputs, per-call ledger row
  (use case, tier, model, tokens, cost when reported, latency, outcome,
  correlation id), streaming only for user-visible text. Model API keys
  come from env at host start and live in host memory (never the store);
  the sidecar receives its model config over the init handshake.
- **D3 (astra-cli)**: the `cli/` crate ships the agent-first binary:
  verbs for the surfaces that exist (`accounts list`, `folders list`,
  `messages list`, `messages read`, `drafts save`, `drafts discard`),
  every verb `--json` with a versioned envelope (`{schema: 1, ok, data |
  error}`), mutating verbs `--preview`, every invocation audit-logged with
  its correlation id (`--correlation-id`, generated when absent), send-class
  verbs refused outright (none exist yet; the refusal is structural in the
  arg parser). Reads open the engine store at the data dir
  (`ASTRA_DATA_DIR`, defaulting beside the product store); draft writes go
  through the engine's `put_draft`/`delete_draft`. The binary builds in CI
  and is staged as the Tauri `externalBin`.
- **D4 (sidecar)**: `sidecar/` ports the kylins skeleton trimmed: esbuild
  single-file CJS bundle, the JSONL protocol mirrored in TS and Rust
  (`init`, `prompt`, `abort`, `command`, `permission_response` down;
  `ready`, `event`, `done`, `error`, `result`, `llm_call`,
  `permission_request`, `tool_result` up), the pi SDK session under one
  model registration, `safeExec` (scrubbed environment, prefix allowlist
  `astra-cli` only), the fail-closed permission bridge (host-pushed policy
  table; gated tools need approval), and the tool set the surfaces allow:
  `list_folders`, `list_messages`, `read_message`, `save_draft`,
  `discard_draft` (mounted through safeExec over astra-cli; archive and
  labels arrive with their slices). One pipeline version constant. Test
  harness: the MockHarness fixture pattern (no network).
- **D5 (host agent module + panel)**: `client/desktop` gains the relay
  (spawn Node >= 22 from PATH or `ASTRA_AGENT_NODE`, version gate,
  stale-generation supervisor with linear backoff and a Lost state), the
  permission bridge routing `permission_request` to a Tauri event and
  `permission_response` back, `agent_prompt`/`agent_abort`/`agent_status`
  commands carrying a per-prompt correlation id, `llm_call` envelopes from
  the sidecar written to the ledger, and tool-result events carrying the
  correlation id end to end. The SPA gains a minimal AgentPanel: chat log
  with streaming text, input box, approval card for permission requests.
- **D6 (traceability contract)**: one correlation id per agent turn:
  generated by the host at `agent_prompt`, propagated to the sidecar in
  the prompt envelope, into every tool exec (safeExec env), into the CLI's
  audit rows, into sidecar-reported `llm_call` rows, and into the
  background client's ledger rows. The audit log records every CLI verb
  with argument preview and outcome; the ledger records every LLM call
  from either path.

## 3. Testing

- Unit (astra-ai): registry table resolution and fallback order; ledger
  and audit round trips against an in-memory store; correlation id
  propagation types; hardening wrapper tags.
- Client (background): a local one-shot HTTP server fixture drives both
  protocols (success, retryable failure triggering the fallback tier,
  quota error, malformed JSON repaired); ledger rows asserted.
- CLI: per-verb unit tests over an in-memory engine; envelope schema
  pins; preview output equals the action's description; audit rows carry
  the correlation id; unknown verb exit code.
- Sidecar (node --test + MockHarness): protocol round trips; permission
  gating is fail-closed (an unapproved gated tool refuses); tools dispatch
  to a stub CLI binary; the bundle builds.
- Host: supervisor tests with a stub sidecar script (ready handshake,
  generation rejection, backoff steps); permission round trip; ledger
  write of a sidecar-reported call.
- E2E (offline): host + real sidecar + stub CLI: one scripted conversation
  exercises prompt, a gated tool approval, an llm_call ledger row, done.
- Live LLM: a manual smoke checklist for the author with their provided
  connection info (requested at review time); no automated network test.

## 4. Acceptance criteria

1. Gate, workspace tests, cargo doc, desktop build, web build and vitest
   green; the sidecar bundle builds and its node tests pass in CI.
2. The offline e2e conversation runs end to end: prompt streams a reply,
   a gated tool call surfaces an approval card, approval executes the CLI
   verb, and the audit and ledger rows land with the same correlation id.
3. A background-client call (fixture server) falls back across tiers on a
   retryable error and lands one ledger row per attempt.
4. The CLI refuses send-class verbs structurally; every shipped verb
   honours `--json` and `--preview`.
5. `docs/capabilities.md` rows move (AI foundation rows, CLI rows) with
   the zh mirror, a changelog fragment, and `docs/ai-foundation.md` (the
   sidecar three-principle contract, the registry, the traceability
   contract, the eval-harness deferral to A1) in the same change.

## 5. Out of scope (A1+)

Feature prompts and evals (the eval harness lands with A1, per the
rulebook's eval rule the sidecar's pipeline constant bumps when prompts
change), memory and compaction, tier settings UI, DLP redact/block
enforcement, archive and label tools, MCP, the weekly spend guard's UI.
