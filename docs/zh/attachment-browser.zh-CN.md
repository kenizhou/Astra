# 附件浏览器：Astra Mail 契约

**范围。** 跨邮件的附件浏览：一个临时模态，列出邮件中的附件，按发件人分组、
按 mime 过滤，带另存为与打开源邮件。约束交付该浏览的每个表面。引擎没有跨邮件
的附件索引，因此这是在引擎既有接缝（搜索 `has_attachment`、解析、
`message_attachments`）之上的有界扇出，一个返回列表与覆盖报告的命令（绝不是新
Surface），以及一个模态覆盖层（绝不是第四个视图）。不改引擎。缺口记录在末尾，
绝不静默。

**原则。** *浏览是命令，不是 Surface，也绝不是文件夹。* 它每次打开都重算，
不发布任何东西：没有要发信号的快照，也没有要保持新鲜的持久索引。壳的导轨与
`ShellView`（mail/calendar/people）不动；模态停靠在壳的尾部、命令面板旁边，
沿用快捷键帮助自己的覆盖层模式。

## 参考偏差，已升级

锁定的 kylins 参考（附件索引、附件浏览器特性）构建一个可重建的 SQLite 索引，
采用仅缓存扫描：它读取已缓存的原始源，绝不拨号服务器（未命中计为跳过）。
Astra 唯一的引擎接缝（`message_attachments`）是缓存优先，但未命中会取回，
且 engine-api 不暴露仅缓存的附件读取。本切片交付有界的未命中取回（不改引擎）：
首次打开经网络预热被扫描邮件的源，受扫描上限约束，覆盖页脚诚实陈述窗口。这是
对参考仅缓存扫描的刻意偏差，在此与 PR 中升级，而非静默。理由：仅缓存接缝将是
engine-api 的 vendor 编辑（每次上游同步后重新施加）；有界取回保持引擎边界干净、
切片自包含。若所有者要参考保真，仅缓存对等（一个 `cached_message_attachments`
接缝）是具名后续。

## 聚合

`attachment_browser(filter)` 逐账户句柄运行（搜索服务的扇出模式）：
`search_mail("has_attachment:true", 200)`，命中经 `mail_by_keys` 按最新优先解析，
然后逐邮件 `message_attachments`，可下载部件摊平在源行元数据旁（账户、键、
主题、发件人、发送时间）。扫描上限为每账户 200 封邮件（预热的工作上限；
kylins 用 500，更小的界限已陈述）。发件人过滤在取回前收窄（被过滤丢弃的邮件
绝不拨号）；mime 过滤收窄一封已列出邮件贡献的部件。

逐邮件失败记录并继续（尽力而为）：拒绝的源或不再解析的邮件是跳过，绝不致使
浏览致命。逐账户失败（没有可读取的 provider、被拒绝的查询或解析）是命名该账户
的诚实错误条目。答案携带跨账户最新优先的行，旁附覆盖报告：scanned（store 解析
的标记邮件）、indexed（部件已列出的邮件）、skipped（拒绝的读取）、失败账户、
以及扫描窗口。

### has_attachment 猜测

`has_attachment` 标志在源 落定 之前是 provider 的猜测。无部件的真猜测贡献
零行（源读取了，部件为空，该邮件计为 indexed）；携带部件的假猜测被查询遗漏。
引擎在源被缓存时 落定 该标志（预热或浏览自己的未命中取回），因此一旦
读过的邮件其标志即真相；该告诫对从未打开的邮件成立。覆盖报告陈述窗口，使有界
答案绝不声称整个邮箱。

## 视图模型与命令

视图模型（`astra-viewmodel::attachment_browser`）携带条目：部件元数据
（id `u32`、file_name、media_type、size）旁附源引用（`MessageKey`，账户与键）
与源行的主题、发件人、发送时间，外加覆盖报告。新类型跨越边界；部件 id 保持
保存命令所取的邮件作用域 `u32`。桌面命令位于 `commands/attachment_browser.rs`
（`commands.rs` 已到上限），经新的 `AppPort` 方法拉取；空白过滤腿作为缺省跨越，
绝不作为匹配不到任何东西的字符串。web 线路类型与包装器停靠
`services/attachments.ts`（绝不 `ipc.ts`，已到上限）。

另存为原样复用既有 `save_attachment` 命令：浏览器行携带它命名的账户、键与
部件 id。打开源邮件派发 `intents.openMessage` 并关闭模态（通知历史先例；相对
kylins v1 是增项，后者没有此动作）。

## 模态与入口

一个临时覆盖层，复制快捷键帮助模式：zustand `isOpen` 门、关闭时为 null、
`useDialogFocus`、Escape 与背景关闭、`role="dialog"` `aria-modal`。行按发件人
分组（最新优先的组，每组旁附计数与总大小）。mime 标签（All 加按计数的前几个桶，
所有 image 折叠为 Images、`application/pdf` 折叠为 PDF）派生自未经 mime 过滤的
快照，因此活动过滤绝不折叠标签；mime 收窄在该快照上客户端运行。发件人预过滤
横幅带清除；覆盖页脚陈述 indexed 计数、跳过、扫描窗口与失败账户，旁附刷新；
空状态告诉读者打开邮件，使其源落入缓存。预览保持占位符（阅读窗格先例；字节
线路是后续）。入口是一个面板命令（固定搜索的形状）；store 接受发件人过滤，
因此 ContactDetail 入口以后添加很便宜。

## 已知缺口

- **仅缓存参考对等**（一个 `cached_message_attachments` 引擎接缝）是已升级偏差
  的后续；本切片未命中取回，有界。
- **has_attachment 猜测**：携带部件的假猜测在源 落定 之前被遗漏。
- **无持久索引**：浏览每次打开重算（kylins 持久化直到清除）。
- **预览**保持占位符；返回字节的预览线路是后续。
- **无 ContactDetail 发件人预过滤入口**（store 接受发件人过滤）、无日期界限 UI、
  无全部清除动作。
- **CLI 附件列表动词**是后续（只读 messages list/search 形状）；v1 不需要 MCP
  工具。
