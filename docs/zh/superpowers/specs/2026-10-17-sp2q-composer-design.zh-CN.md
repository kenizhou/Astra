# SP2q 设计：编写器收尾

**状态。** 2026-10-20 决定。各切片在本提交处从 main 分出。

**范围。** 待办清单点名的、以及其中仍然剩下的部分：格式工具栏缺的
另一半（字号、文字颜色、高亮；粗体、斜体、下划线、列表与撤销已
交付）、完成的链接（就地编辑与移除、输入的地址变成链接、方案检查
浮出）、端到端的签名（核心里无人使用的 Signature 块接到设置编辑器、
按账户指派、种子植入，以及随 From 的自动切换）、带应用级默认发送
账户的 From 选择器、向正文粘贴图片（补完“内联与附加文件”），以及
mailto: 入口（核心的解析器终于被消费）。附加与拖拽已随 SP2p 落地，
不再重复划入。

## D1：格式补完

线路已经携带字号（四档）、文字颜色与高亮；编辑器把这样的 run 当作
无人能编辑的保留内容。工具栏补上三个控件（一个字号循环、两个取自
应用调色板的颜色选择器），编辑器的标记随之增长，文档线路的可编辑
run 规则双向放宽以接纳这三个标记：在编写器里排版的 run 往返，其他
客户端排版的 run 变为可编辑而非冻结。工具栏的铬件以共享目录中的
应用语言呈现。

## D2：完成的链接

链接按钮长成就地弹层：目标与显示文本并排，可在选区上设置与移除。
输入的地址在词语离开插入点时变成链接（空格或回车把带分隔的 http、
https、mailto 或 www 前缀提交为链接 run；识别器在客户端且保守）。
方案允许清单仍留在核心侧且绝对（http、https、mailto 与长度上界）；
编写器在发送前校验文档的目标并指名将退化的链接（工具栏下的一句
话，绝不是阻止发送：核心退化为纯文本仍是发送自己的底线）。

## D3：签名

核心的 Signature 块终于有了生产者。设置新增签名编辑器：富文本
（D1 放宽的同一套标记），写一次，按账户指派（一个账户为新邮件播种
的签名、一个为回复播种的签名；同一个可以兼任）。编写器在打开时
播种该块（新邮件在最上，回复在引文之下），From 选择器的切换替换
那个用户未改动过的播种签名（被编辑过的签名属于用户，保持不变）。
发送渲染文档携带的内容（渲染器已经输出该块；纯文本腿携带 RFC
3676 分隔符）。内嵌标志不随本切片（签名里的图片需要在播种时绑定
附件）；它作为该行点名的缺口记录。创建 signatures.md 及 zh 副本。

## D4：From 选择器与默认发送账户

外壳的账户行在显示名旁获得发送地址。From 字段变成选择器：账户
列表、默认者居先、选择按 D3 的规则替换播种的签名。设置新增应用级
默认发送账户（一个偏好；新邮件按钮与 mailto: 入口以它打开，未设置
时回退第一个账户）。从请求（回复、转发）打开的编写保留请求的
账户，绝不重选。

## D5：图片粘贴与 mailto: 入口

向编辑器粘贴图片与拖放一样播种（内联处置、cid 绑定、可移除的
行），补完内联与附加文件的弧线；粘贴文本不受影响。mailto: 入口：
宿主的深度链接监听器（以及单实例参数路径）把 mailto URL 交给应用，
核心的解析器把它变成预填（它尊重的五个字段，其余全部丢弃，正如
RFC 6068 说客户端可以做的那样），编写器以默认发送账户打开并预填。
在阅读面板里点击 mailto: 链接同样打开编写器，而不是操作系统的
邮件应用。

## 已知缺口如实记录

- 表格不随行（该行点名行列编辑；线路把 Table 块作为保留内容携带，
  编辑器冻结它们）。
- 缩放手柄不随行（粘贴或引用的图片保持其尺寸；线路的 width_px
  随块走，不随手势）。
- 内嵌标志不随 D3（播种时的附件绑定是它自己的改动）。
- 输入地址识别器只尊重带分隔的 ascii 前缀；裸域名永不变成链接。
- 方案检查的浮出是一句话，绝不是阻止发送：核心的退化仍是底线。

## 测试先行

每个行为与其红灯一起落地：线路对三个标记的往返、识别器的提交与
拒绝、签名播种与未改动切换规则、选择器的账户列表与默认偏好、
粘贴播种、mailto 解析到预填（解析器的测试已在；宿主缝离线钉住），
以及 T4 的实测：带格式的发送在测试服务器上往返（收到的正文携带
字号与颜色）、带签名的发送往返、链接往返包括被拒方案退化为纯
文本。
