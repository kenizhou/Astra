# SP2v 设计：IMAP/SMTP OAuth 登录

**状态。** 2026-10-25 决定。各切片在本提交处从 main 分出。

**范围。** mail-oauth 行：服务器提供时以提供商身份登录 IMAP/SMTP，依据
标准发现。引擎交付了整个承载半边（预认证探测、两条腿上的 SASL
OAUTHBEARER 与 XOAUTH2、带一次续期的按拨号凭据源）；参考契约
（mail-calendar 的 mail-oauth.md，十一条规则）就是要移植的。Astra 补上
授权、发现链、拨号臂与屏幕；静态提供商表按参考规则交付为空。

## D1：先问与三屏

先问服务器：向导的 IMAP 步骤探测所拨服务器的预认证 CAPABILITY 与
EHLO（引擎的动词，什么都不发送，连接关闭）。三种回答构成三屏：提供
OAuth 时登录按钮为主、密码字段降级到次级控件之后（绝不移除）；提供
OAuth 但无已注册路由时显示"仅接受预注册应用"句子、密码站立；不提供
OAuth 时如今日的密码表单。密码仅在服务器接纳处提供
（AUTH=PLAIN/LOGIN 或无 LOGINDISABLED）；两者都不接纳的服务器是既有
的不可用服务器错误。

## D2：发现链

签发者来自提供商自己的 autoconfig `<oAuth2><issuer>`（自动检测 crate
已解析并按信任过滤：ISPDB 与不受信跳数被丢弃），否则是电子邮件域名
及其可注册域名的 RFC 8414 well-known。RFC 9728 挑战路线是 JMAP 的腿，
留在那里。动态注册（RFC 7591）在服务器提供时铸造客户端，像 JMAP 的
一样按会话缓存；静态 mail-providers 表交付为空，缺席的 client id
意味着不提供该路由，绝不发明。每一次失败都是密码字段。

## D3：授权与拨号

登录的 IMAP 账户在其节旁存储 OAuth 授权（JmapOAuthGrant 的形状模型：
client id、refresh token、端点、redirect、scopes、issuer），无密码。
拨号以共享 GraphTokenSource（single-flight、冷却、经汇聚点的轮换）
构建引擎的 OAuth2 凭据，按连接询问一次并带引擎自带的一次续期重试；
被拒 token 上的重拨是引擎的，不是重连包装器的。SMTP 提交腿以同一
token 经它自己的机制选择呈现。引导时的死授权记录过期登录状态
（imap_smtp 种类的行指名被拒凭据；该族绝不与 JMAP 或集成族共享
授权）。

## D4：界面

向导的三屏（D1）；完成遵循 JMAP 模型（拨号表条目先于拨号注册，使拨号
中的轮换落地；add 与 rotate 的事务）；账户页的过期行为 imap_smtp 族
补上诚实形状（指名被拒凭据；补救是重连账户，直到就地授权交付，与
JMAP 行的形状一致）。`iss` 在宣告处严格校验；`resource` 不发送（参考
的有意为之）；没有机制旋钮（引擎的偏好顺序站立）。

## 已知缺口如实记录

- 静态 mail-providers 表交付为空：没有已注册的提供商 id、没有提供的
  路由，行的诚实状态。
- 测试服务器不服务 OAuth 签发者（JMAP 切片的发现）：实测证明钉住探测
  的三种回答与发现的软失败；完整链路的实测等待真实 IdP，与 JMAP 的
  一样。
- 密码族的过期行（被拒的密码）保持不变（账户行已报告它）。
- RFC 7628 挑战探测与 RFC 8707 resource 留在外面，恰如参考规则。

## 测试先行

每个行为与其红灯一起落地：脚本化 offer 上探测的三屏；签发者链
（autoconfig 路线、两个 well-known 候选、拒绝形状）；注册缓存；授权
的往返与无密码规则；OAuth2 凭据的按拨号询问与一次续期重试；死授权
的过期行；屏幕的渲染（密码降级、绝不移除）；以及实测：测试服务器的
真实能力行钉在两条腿上、发现在测试服务器上的软失败。
