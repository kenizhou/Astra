# SP2x 设计：表面收尾

**状态。** 2026-11-07 决定。各切片在本提交处从 main 分出。

**范围。** 矩阵仍持未开始的六个表面行：草稿行重新打开编写器、图片缩放
手势、按行的永久删除、启动日历抓取、周期日历刷新、演示旗标。各行
需要的引擎动词都已在内嵌树中；本切片是应用层接线与手势。

## D1：永久删除

一个动词端到端：经 MailEdit::delete 的 delete_message 核心函数，走其他
写动词同乘的发件箱中介编辑路径，一个意图，一个确认门控的行菜单项。
句子复制回收站文件夹删除自己的形状（"This cannot be undone."），该
项在菜单打开的任何地方站立、危险样式、位于普通 Delete（保持为移入
回收站）之下。回收站的批量删除保持自己的表面。

## D2：启动日历抓取

日历不打开就填充：引导的每账户首次同步 spawn 加入日历抓取，与邮件
同步 join，使一个连接的账户也刷新其日历一次。刷新体被直接调用，
绝不经意图（启动时的意图会无谓地重发布日历表面）；绘制半边已交付
（引导时的存储 prime），因此之前同步过的日历在启动时绘制、抓取
填充应用离开期间变化的东西。任何时候添加的账户获得同一 join。

## D3：周期日历刷新

投递循环旁的宿主计时器：五分钟一跳，门控于至少一个账户已连接
（拨号表非空），调用非意图刷新体使表面信号只在变化时触发。间隔
可调试覆盖（带限度的环境覆盖，供确定性测试，参考自己的形状）。
参考的已知缺口如今由我们关闭：应用保持打开期间的常设节奏。

## D4：草稿行重新打开

一行草稿经同一副本打开回编写器：最新条目旁的按键 resume_draft
（消息引用指名账户与键；三道拒绝门移植——不可解析、非草稿、正文
不可读），恢复携带草稿附件作为可移除的预附行（转发自己的形状；
携带部件走核心侧部件 id 载体；字节绝不二次跨越宿主边界），下一次
保存覆写同一键与 Message-ID（采纳机器已如此键控）。两个行菜单动词
落地：Open（恢复进面板）与 Delete Draft（丢弃机器覆写该行的键，
失败时发件箱排队）。

## D5：图片缩放

编写器插入的图片渲染（今日它暂存为带药丸的文本行）：内联图片在
编辑器旁渲染为可见图片（保留块分离使铬件不进消息），缩放手势移植
——内容外固定覆盖层上的指针事件、角柄、拖拽宽度钳制（24px 下限、
可用宽度上限）、高度仅在标签已声明时跟随、只有宽度上线进入图片
内联的 width_px。被引用原图保持其 width/height 属性（净化器保留
它们）；本切片的手势覆盖编写器插入的图片，被引用原图的手势记录为
该行的有名余量（引用 HTML 今日不渲染）。

## D6：演示旗标

调试门控的启动旗标启动夹具外壳：旗标站立时桌面宿主的命令层应答
已记录的快照，因此生产 webview bundle 不经修改地对夹具答案运行
（把夹具挡在生产之外的别名规则保持原样）。门限仅调试构建；屏幕
选择器（哪个表面站立：列表、阅读、设置、联系人）作为环境变量
移植；快照的日期按记录站立（冻结的时钟，seeded_now 想法的近似）。
参考的内存提供者引导记录为不采取并附原因（未内嵌的绑定代码对上
拨号优先的引导；截图运行不需要真实引擎保真）。

## 已知缺口如实记录

- 被引用原图的缩放手势随后续切片（引用 HTML 今日不渲染）。
- 演示夹具是无固定挂钟的静态记录；日期按记录冻结。
- 周期刷新节奏固定为五分钟（无设置）。
- 永久删除的确认是行菜单自己的；其身后没有撤销（引擎动词不可逆）。

## 测试先行

每个行为与其红灯一起落地：伪件上的删除动词及其确认门控菜单项；
启动抓取 join（日历在视图未打开时填充、表面信号沉默）；周期跳
（门控、可调试覆盖、只在变化时的信号）；按键恢复（三道门、携带
行、同键保存）；渲染的图片与手势（钳制宽度、比率规则、线路只带
宽度）；演示旗标（门限、屏幕选择器、未修改的 bundle）；以及实测：
测试服务器上观察到的删除动词（副本真正消失）、启动抓取填充日历、
草稿重新打开往返（保存的草稿、打开的行、落在同键上的保存）。
