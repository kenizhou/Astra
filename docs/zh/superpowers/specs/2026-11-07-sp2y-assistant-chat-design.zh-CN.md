# SP2y 设计：带工具预算的助手聊天

**状态。** 2026-11-07 决定。分片自此提交切出主干。

**范围。** A2 行：可调用工具的助手聊天，受一个挂钟式工具预算约束。参考是
inbox-zero（`refs/refs-lock.toml` 中的 `ai-design` 锁），不是 mail-calendar，
后者没有聊天界面；调研记录在本分片的台账里。

**许可立场，先说清楚。** inbox-zero 是附加了商业条款的 AGPL-3.0（其许可证加
了变现限制与企业使用限制）。本分片采取的是既有立场（`ai-foundation.md` 的
用例表移植）：移植**契约与行为**，注明来源文件与仓库，代码以 Astra 自己的
惯用法在 GPL-3.0-only 下重写。不复制任何 inbox-zero 文件；不触碰任何
allodia 许可的代码（聊天路径完全不引用 mail-calendar）。

已存在且原样复用：sidecar 的 JSONL stdio 循环及其完成信封保证、跨宿主边界
的流式事件、权限桥（默认关闭，缺行即需批准）、台账（每次 LLM 调用、工具
调用与权限决定都带关联 id）、层级注册表的 AssistantChat 解析、中止语义、
以及那一个流式聊天面板。本分片新增：预算、带 CLI 动词的搜索与操作工具、
聊天持久化与线程、结构化工具展示加 markdown、以及流水线版本戳与其评测。

## C1：工具预算

参考的预算自回合开始的挂钟；超时后模型失去工具（活动集清空、工具选择为
无）并以纯文本收尾；其界面对此一声不吭。Astra 的界受运行时所限更粗（代理
运行时没有逐步钩子），本规范如实说明：

- 时钟自收到提示词起走（提示词运行器的一回合）。
- 超出预算的工具执行以测试工具已报告的“跳过”结果回答模型（绝不静默丢
  弃；审计行照落地，与被拒工具一样），模型由此以唯一可能的方式得知预算：
  被告知不行。
- 看门狗在硬上限（预算加宽限）处中止回合，以一个 DONE 信封加状态事件落
  地，绝不挂起提示词：完成信封保证在每条路径上都成立。纯文本回合完全没有
  工具门，这正是看门狗不可省略的原因。
- 一个 `budget-spent` 状态事件跨到面板（参考的沉默不是要照抄的契约）：回
  合进行中有一条状态行，预算咬合时有一条说明。
- 仿真相手（mock harness）以同样方式门控，否则端到端证明什么也证不了。

## C2：搜索与操作工具

- CLI 新增邮件操作动词（messages mark-read、set-flagged、archive、trash；
  每个都按 CLI 规则带 `--json` 与 `--preview`），与只读家族并列，外加
  messages 搜索动词（MCP 面的搜索形状即契约；应用层的动词已存在）。
- sidecar 在五个邮件工具旁新增这些工具，经策略表确认门控（读自动、操作需
  确认、其余默认关闭），运行时允许表扩展，技能索引措辞更新，写明助手现在
  能做什么、发送仍由人完成。
- 搜索工具分页（每次二十条）并带 has-more 回答，即参考自己的分页纪律；
  工具输出在线上是字符串，因此截断策略采用参考的上限（读取的 四千字符
  上限、日志的 二百）。
- 任何地方都不存在发送工具（CLI 没有发送动词、MCP 面没有发送工具、
  sidecar 对代理拒绝发送类动词）：结构性拒绝即契约，不变。

## C3：持久化与线程

- 聊天与消息行作为一次新迁移落进 AI 存储：聊天的 id、标题、创建与最近触
  及时刻，消息的角色、parts（渲染后的回合）与运行元数据。
- 每个提示词走自己的会话 id（按聊天，而非固定的主会话），由 sidecar 已读
  取的 session id 路由。
- 面板新增线程列表，带载入、列出、重命名与删除命令。
- 可见日志只有一个事实来源：存储的行。运行时自己的会话文件留在代理数据
  目录里做机房内部事，界面绝不加载；两者可能不一致，只有存储的答案上屏。
- 早前裁剪的“无会话镜像”只为这个镜像重开；压缩与记忆抽取**留在界外**
  （记为该行的具名余项，不是悄悄丢弃）。

## C4：工具展示与 markdown

- 便签行变成结构化工具卡片（名称、参数摘要、状态、截断后的输出）。
- 助手文本以 markdown 渲染；依赖在实现时裁定（小渲染器、沙箱化、无原始
  HTML；编写器安全文档的净化纪律适用于所渲染内容）。

## C5：流水线版本与评测

- 每次运行把自己的元数据打上流水线版本戳（聊天行的元数据字段；本分片不
  给台账本身加列）。
- AI 行为变更随其评测交付：场景落在 `evals/` 下钉住预算行为（超预算的工
  具调用答跳过；看门狗以 done 落地；预算事件跨过边界），版本在同一变更里
  递增。

## 已知缺口，记录而非隐藏

- 压缩与记忆抽取留在界外（参考的聊天压缩与聊天记忆本分片没有对应物）。
- 内联邮件卡片留在界外：草稿卡片即待定动作（草稿工具已交付），参考的内
  联卡片提示纪律不移植到一个阅读面板本身就渲染邮件的产品。
- 预算只有挂钟；没有每回合的令牌或步数上限（参考的步数同样无界）。
- 聊天是单用户本地的；跨重启无可恢复流（参考的恢复是 Astra 没有的服务器
  形状）。

## 测试先行

每个行为随其红灯落地：仿真相手上的预算工具门与看门狗（跳过结果、审计
行、完成信封、状态事件）；动词的 `--json` 与 `--preview` 钉；工具的确认
门控与截断上限；迁移的行与按聊天路由的会话；卡片与 markdown 渲染；版本
戳与评测场景；以及真件上的实证：一个聊天回合搜索播种的邮件、经确认门操
作一行、在武装的短预算处失去工具、回合仍以 done 落地。
