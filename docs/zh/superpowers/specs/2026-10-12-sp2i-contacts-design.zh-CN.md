# SP2i 联系人设计

日期：2026-10-12
状态：proposed
父规范：`docs/superpowers/specs/2026-08-...-workflow-design`（第 5、15 节）
移植契约：实质移植 mail-calendar 的 `docs/contacts.md`；头像规则引自其
`avatars.md`；切片前调研见
`.superpowers/sdd/2026-10-12-sp2i-contacts/survey.md`。

## 1. 目的

联系人作为一个完整的产品表面：带合并披露的统一人员列表、带逐值出处的
人员详情、在选定的可写卡片上创建与编辑联系人、共享同一索引的撰写收件人
自动补全、头像，以及最终在启动时拨号日历与联系人两条腿的账户模型 DAV
扩展（关闭日历契约记录的首条缺口）。

## 2. 决策

- **D1（表面）**：`Surface::People` 携带 `PeopleSnapshot`：统一行（显示
  名、引擎给出的首字母与颜色、账户数披露、节字母、主地址）、打开人员
  的详情（按账户命名的来源卡片、逐值出处、可编辑卡片集合）、写入状态、
  以及创建目标（可写通讯录）。外壳视图切换在 Mail 与 Calendar 旁增加
  People。
- **D2（意图）**：`People(PeopleIntent)` 族：`Refresh`、`Search { query }`
  （匹配在引擎中完成，绝不重筛已载行）、`OpenPerson`、`ClosePerson`、
  `CreateContact { book, draft }`、`UpdateContact { card, patch }`。无
  删除：移植的契约不提供（记录为缺口）。
- **D3（合并及其披露）**：引擎判定谁是一个人（仅按共享的规范化地址
  合并；绝不按姓名、电话或机构），客户端渲染人员而非卡片。合并行披露
  `In N accounts`（去重账户数，由核心计数，为一时不显示）；详情在
  Also in 下点名来源。后台合并后退役的人员 id 仍可解析。排序、匹配、
  节字母（重音字母是字母；其余入 `#`）与首字母均由引擎决定。
- **D4（写入命名卡片）**：编辑携带 `(person, account, card)`，编辑器从该
  卡片播种，绝不用合并后的详情；多于一张卡时由客户端选择。仅当存在可
  写目标时显示创建；仅当存在可编辑卡片时显示编辑；两者皆无的人员用文
  字说明。patch 只命名变更的字段，且在卡片已有属性之上重建；仅在有姓
  氏时写结构化姓名；创建必须可再找到（姓名、机构或地址）。写入状态沿用
  日历的形态外加 `Invalid`（另一句话，显示在表单下）；`Failed` 指未确
  认而非被拒绝，状态行位于列表旁。
- **D5（自动补全）**：撰写收件人字段只补全最后一个逗号之后的 token，
  插入裸地址，查询引擎的排序建议（卡片加已发邮件历史；仅历史条目绝不
  隐藏；空查询不返回），把已完成的收件人画为带逐个移除控件的药丸，而
  字段始终保持一个逗号分隔字符串；列表悬浮于表单之上（不透明、不夺焦
  点、仅聚焦字段的列表、越过编辑器时清除）。播种字段规范化其初始值并
  与之比较脏状态；插入符默认落在 To，撰写已带地址时落在正文。
- **D6（DAV 账户扩展）**：`AccountConfig` 增加可选的 `dav` 节（来源与凭
  据；CardDAV 腿按移植规则回退到 CalDAV 来源），账户层在邮件提供商之
  旁拨号 CalDAV 与 CardDAV 提供商，桌面启动安装拨到的每条腿。日历与
  联系人两条腿一起落地：一次账户模型扩展，关闭两个缺口。
- **D7（头像）**：首字母与颜色由引擎决定，同一人员不会在不同表面上不
  一致；照片经引擎的缓存联系人照片抓取到达，所有显示该人员的表面共享
  一次解析（本切片覆盖联系人行与阅读头；邮件行随列表打磨跟进）。

## 3. 测试

- 单元（astra-app，引擎 fake）：快照重建（合并披露事实、节折叠、排序平
  局裁定）；写入路径（命名卡片纪律、只写变更字段、姓氏规则、可再找到
  拒绝、状态映射）；自动补全 token 数学（纯函数）。
- 线协议：PeopleIntent 族 + PeopleSnapshot 字面量钉住，双语言。
- 前端（vitest）：带节与披露的列表；带 Also-in 与出处的详情；编辑器的
  卡片选择与条件入口；药丸、悬浮列表、插入符规则（jsdom 诚实）。
- 实测（门控，harness）：Stalwart 的 CardDAV 在 2080 提供通讯录与卡片；
  一次同步读取、一次写入可写通讯录、一次编辑往返、跨两个 harness 账户
  存档的合并人员（`In 2 accounts` 披露实测）、以及邮件套件已播种的已发
  邮件历史上的自动补全。

## 4. 已知缺口（预记录）

- 无联系人删除（移植契约与日历写入的离线耐久一并延期）。
- 同事目录（Graph users、Workspace 目录）需要 OAuth 账户切片；不在本切
  片。
- JMAP 联系人适配器随引擎交付，但本切片未对 harness 的 JMAP 面实测；
  CalDAV/CardDAV 是实测的一对。
- 邮件列表行上的照片随列表打磨切片跟进。
