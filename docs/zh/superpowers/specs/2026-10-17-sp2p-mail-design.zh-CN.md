# SP2p 设计：邮件批次

**状态。** 2026-10-17 决定。各切片在本提交处从 main 分出。

**范围。** 待办清单点名的邮件批次：文件夹管理（新建、重命名、移动、删除、
拖拽）、双向附件、多选操作、统一的 All Accounts 组，以及移至文件夹。引擎
已经交付本切片接线的每一个动词（edit_mailbox 的 create、update、trash、
delete；MailEdit::MoveTo；message_attachment 字节读取；编写器的 blob
句柄）；Astra 今天一个都没有消费。本切片是接线与界面，附带实测证明与各行
引用的文档。

## D1：经应用核心的文件夹管理

FolderIntent 从它唯一被拒绝的 Create 长成引擎的四个动词：Create、Rename
（携带新名的 Update）、Move（携带新父级的 Update）、Trash，以及 Delete
（永久，仅在 Trash 内部或确认之后提供）。派发把每一个映射到引擎经发件箱
中介的 edit_mailbox，并铸出幂等键，因此离线排队的文件夹编辑会在服务器
回来时落地。账户的能力快照为界面设门：没有 mailbox_writes 的 provider 不
显示文件夹编辑动词，绝不显示一个点击即失败的禁用菜单项。删除先进
Trash（Trash 动词）；永久 Delete 是 Trash 自己菜单提供的动词，在确认
对话框之后。重命名或移动后按返回的键重新选中该文件夹（回执指名编辑
最终落到的文件夹；IMAP 重命名铸出新键）。

## D2：统一的 All Accounts 组

Scope::AllInboxes 获得行：快照合并每个账户的收件箱行，最新在前，与每
文件夹列表渲染的行形状相同（RowKey 按设计绑定账户，因此选择与操作无需
改变）。面板的统一行变为可用：点击选中该作用域，它已在渲染的未读徽记
继续计数，且该选择跨启动持久化（作用域搭载设置切片已建立的持久化 UI
状态）。搜索保持它自己的作用域；统一列表是列表，不是搜索。

## D3：移至文件夹

一个 MoveTo 意图（一组行、一个目标文件夹键、单一账户：移动留在账户
内，这是行自身的约束）。行菜单的占位符变为该账户文件夹的子菜单（不含
mover 账户），多选批处理像其他批操作一样循环它。引擎的 MailEdit::MoveTo
经既有的发件箱路径完成工作；目标是面板投影的文件夹键，移到行已在的
文件夹是不排队即由应用答复的空操作。

## D4：文件夹拖拽

文件夹树长出 HTML 拖拽：同账户内一个文件夹拖到另一个文件夹上重定父级
（Move 附带后代守卫：文件夹不能落入自己的子树，应用在任何排队之前
拒绝）；拖到账户行上使之成为根；把消息选区拖到文件夹上移动这些行
（D3 的意图，同一循环）。拖拽只携带键，绝不携带邮件内容；合法目标
悬停时高亮，非法目标（跨账户、入后代、落在统一行上）时拒绝。

## D5：双向附件

读取侧：阅读面板的 Save As 与 Download All 变为真实。SaveAttachment
意图携带行引用与附件 id；应用核心经引擎的 message_attachment 读取字节；
桌面宿主以保存对话框应答并返回路径；web 界面显示保存的路径或拒绝。
编写器侧：附件按钮打开宿主文件选择器（多选对话框），每个选中的文件
成为文档中的一个 DraftAttachment，操作行列出它们及大小与移除控件，
发送携带 blobs（线路与核心的解析已交付；编写器不再发送 blobs: []）。
转发打开时持有原件的附件并可逐一移除：转发意图获得原件的附件元数据，
编写器把它们渲染为预附行，被移除的行干脆不随发送走。把文件拖到
编写器上即附加（文档直接附加，图片询问内联还是文件）。

## D6：多选补完

行菜单已循环的批操作（已读、未读、标记、归档、删除）之外，补上 trash
与 delete 的诚实区分：文件夹内的 Delete 是移入回收站，回收站自己的
菜单提供永久删除。选区存在时出现批量工具栏（计数、全选、清除与各
操作），因此整批操作不依赖上下文菜单。邀请自身的 .ics 部件在消息是
邀请时不再列为附件（邀请界面拥有的部件），而真正附上的日历文件仍然
列出。

## 已知缺口如实记录

- IMAP 上的文件夹拖拽以重命名重定父级（该协议唯一的移动）；回执的
  键重选即是契约。
- 携带第二个独立附加日历文件的邀请也会失去那个附件片：隐藏规则按
  媒体类型判别，因为引擎的调度读取不携带部件身份；按部件身份判别是
  后续的引擎面。
- 文件夹意图把文件夹键作为裸字符串携带在 `AccountId` 旁，延续新建
  意图既有的形状；全面迁往 `FolderRef` 的版本化是后续的线路决定。
- 附件预览只打开宿主 shell 能打开的东西（保存的路径）；应用内预览不
  随本切片。
- 统一列表只含收件箱（作用域自己的名字）；可配置的统一集合是后续
  的行。
- 离线文件夹编辑在引擎的发件箱后排队；排队编辑的菜单显示待定状态，
  被拒绝的重放以引擎应答的冲突浮出。
