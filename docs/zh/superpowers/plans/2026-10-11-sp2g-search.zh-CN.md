# SP2g 搜索实施计划（中文审阅版）

> 非规范性译本，仅供审阅；凡与英文版有出入之处，以英文版为准
> （`docs/superpowers/plans/2026-10-11-sp2g-search.md`）。
> 代码块、命令、文件路径与标识符保持英文原样。

> **执行者须知：** 必须配合 superpowers:subagent-driven-development（推荐）或
> superpowers:executing-plans 技能逐任务执行本计划。步骤使用复选框
> （`- [ ]`）语法跟踪。

**目标：** 端到端交付搜索：两个 Intent 与增量搜索状态、引擎搜索面上的
DSL 分解、带深度注记的线程分组、标题栏搜索框与范围下拉、结果渲染与退
出、活体验证、契约文档。

**架构：** astra-app 拥有 DSL 分解、分组与基于 `engine.search_mail` 的
搜索状态；渲染器在有搜索行时择取搜索行；引擎拥有匹配。

**技术栈：** 既有 workspace；锁定 rev 的引擎搜索面（先读）；harness 作
活体验证。

**Spec：** `docs/superpowers/specs/2026-10-11-sp2g-search-design.md`

## 全局约束

- 沿家规：SPDX、500 行上限、deny-everything lints、提交前 gate（直接
  退出码）、conventional commits、无破折号、英式英语、zh 镜像同提交、
  只允许增量线上变更。
- 锁定 rev 的引擎是匹配的所有者；Astra 绝不解析邮件协议。

### 任务 1：协议与状态类型
**文件：** `crates/astra-app/src/{protocol/intent.rs（Search/
SetSearchScope）, protocol_tests.rs}`；`crates/astra-viewmodel/src/
{search.rs, search_tests.rs}` + 快照的增量字段。
**接口：** 两个 Intent（serde snake_case、钉死）；`SearchScope::
{AllExceptTrash, CurrentFolder, CurrentAccount}`（线词）；
`SearchState { query, scope, rows: Vec<MessageRowView>, depth_months:
u32 }`；`MailboxListSnapshot.search: Option<SearchState>` 增量（none 跳
过）。
- [ ] 测试先行：Intent 字面量；状态字面量；增量快照夹具原样。
- [ ] 实现；提交 `feat: add the search protocol and state types`。

### 任务 2：搜索服务
**文件：** `crates/astra-app/src/{search.rs, search_tests.rs}`（+ dispatch
臂）。
**接口：** DSL 分解 `split_query(raw) -> (Option<from>, Option<to>,
text)`；`run_search(query, scope, ...)` 经 `engine.search_mail`（先读
68eab00 的签名：参数、过滤支持、排序）加 APP 侧收窄/分组；同步窗口的深
度注记；线程分组（按线程 id 分组、计数、最新线程优先）；dispatch 臂
（Search 清除/发布；SetSearchScope 对活查询重跑）。
- [ ] 按 spec 单元清单测试先行（分解含畸形前缀；状态发布/抑制；分组/
  排序；深度量化；范围重跑；None 返回）。
- [ ] 实现；提交 `feat: run searches over the engine with grouping and
  depth`。

### 任务 3：宿主 + ipc

- [ ] 测试先行：双侧线字面量。
