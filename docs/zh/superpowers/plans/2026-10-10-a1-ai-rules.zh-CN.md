# A1 AI 规则实施计划（中文审阅版）

> 非规范性译本，仅供审阅；凡与英文版有出入之处，以英文版为准
> （`docs/superpowers/plans/2026-10-10-a1-ai-rules.md`）。
> 代码块、命令、文件路径与标识符保持英文原样。

> **执行者须知：** 必须配合 superpowers:subagent-driven-development（推荐）或
> superpowers:executing-plans 技能逐任务执行本计划。步骤使用复选框
> （`- [ ]`）语法跟踪。

**目标：** 交付带安全默认的裁决原语、规则引擎（生成、匹配、确定性执行、
CLI CRUD）、分类、冷邮件拦截、主动 DLP、带管线常量的 eval 工装、nano
花费护栏、对所供端点的门控活体套件。

**架构：** 裁决与 DLP 在 Rust 客户端路径（astra-ai + client/desktop）；
规则与其执行在产品库上的 astra-app 内；来信通道挂在 refresh 后；CLI 增
规则动词；eval 以门控 cargo 测试运行。

**技术栈：** 既有 workspace；所供 DeepSeek anthropic 端点作活体门（tier 3）。

**Spec：** `docs/superpowers/specs/2026-10-10-a1-ai-rules-design.md` +
`docs/superpowers/specs/2026-10-10-binary-judge-design.md`

## 全局约束

- 沿家规：SPDX、500 行上限、deny-everything lints、提交前 gate（直接
  退出码）、conventional commits、无破折号、英式英语、zh 镜像同提交、
  只允许增量线上变更。
- 所供连接（绝不提交；活体门从环境读取）：`ASTRA_LLM_DEFAULT/ECONOMY/

  `ASTRA_LLM_BASE_URL_ANTHROPIC=https://api.deepseek.com/anthropic`。
- 安全线：裁决只门控 UX；权限桥与发送拒绝不动；prompt 中的邮件内容一律
  包裹；DLP block 从严关闭。

### 任务 1：裁决原语
**文件：** `crates/astra-ai/src/{judge.rs, judge_tests.rs}`（+ 安全默认数
据）、`client/desktop/src/ai/{client.rs, client_tests.rs}`（+ judge 方法）。
**接口：** `JudgeVerdict::{Yes,No,Abstain}`；`JudgeOutcome { verdict,
path: FirstTry|Retry|AbstainDefault }`；`SAFE_DEFAULTS` 表（裁决 spec 的
七个 use case）；`LlmClient::judge(use_case, question, context,
correlation) -> JudgeOutcome`（单 token 模板版本化于
`JUDGE_TEMPLATES_VERSION`；Abstain 同档重试一次；此后适用默认；裁决值入
  台账 outcome；先查花费护栏）。
- [ ] 测试先行：解析器（yes/no/大小写/标点/垃圾→Abstain）、重试状态机、
  默认表钉死（无默认的新裁决 use case 交付即失败）、夹具服务器（线形态、
  abstain、配额跳过）。
- [ ] 实现；提交 `feat: add the binary judge with safe defaults`。

### 任务 2：规则模型、生成、库迁移
**文件：** `crates/astra-ai/src/migrations/0002_rules.sql` + 库 API；
`crates/astra-app/src/ai_rules/{mod.rs, generate.rs, generate_tests.rs}`；
管线常量 `RULES_PROMPT_VERSION`。
**接口：** `Rule { id, name, condition, actions:
Vec<Action::{MarkRead,SetFlagged}>, enabled }`；`prompt_to_rules(text,
correlation) -> Vec<Rule>`（经 complete + repair 的结构化 JSON；生成
prompt 版本化）；库 CRUD。
- [ ] 测试先行：生成形态含修复路径（夹具服务器）；CRUD 往返；封闭动作集
  拒绝未知项。
- [ ] 实现；提交 `feat: add the rules model with prompt generation`。

### 任务 3：匹配、执行、来信通道
**文件：** `crates/astra-app/src/ai_rules/{match.rs, execute.rs}` + 测试；
`crates/astra-app/src/{sync.rs（挂钩）, ai_results.rs}`；
`crates/astra-ai/src/migrations/0003_ai_results.sql`。
**接口：** `match_rules(mail, rules, correlation)`（逐启用规则
JudgeRuleMatch、上下文封顶、结果入 0003）；经既有标记/旗标写路径的确定
性执行（审计）；重建后的有界通道（新见未读头 N；已见不重跑；每通道一个
correlation）。
- [ ] 测试先行（假件 + 夹具裁决）：命中 yes/no/abstain 默认；执行意图被
  记录；N 被遵守；已见跳过；abstain 默认不执行。
- [ ] 实现；提交
  `feat: run rules over incoming mail with deterministic execution`。

### 任务 4：分类、冷邮件拦截、主动 DLP
**文件：** `crates/astra-app/src/ai_rules/{categorise.rs, cold.rs}` +
测试；`crates/astra-ai/src/{dlp.rs, dlp_tests.rs}`（redact 模式；策略）。
**接口：** 分类（五选一结构化、版本化、DEFAULT 档）；冷邮件
（JudgeColdEmail、nano）；`redact(content)`（邮箱、电话形态、长数字串）
与来信通道中任何 prompt 前施加的 `ASTRA_DLP` 策略门
（allow|redact|block）；block 落 outcome `blocked`。
- [ ] 测试先行：类别形态；冷裁决含 abstain；redact 模式钉死；block 路径
  拒绝并入台账。
- [ ] 实现；提交
  `feat: add categorisation, the cold judge, and active dlp`。

### 任务 5：CLI 动词、eval 工装、花费护栏、管线常量
**文件：** `cli/src/verbs/{rules.rs, ai.rs}` + 测试；`evals/` 夹具 +
`crates/astra-app/src/evals/{mod.rs, runner.rs}`（门控）；常量；客户端
路径上的护栏。
**接口：** `rules list|create|delete`（--json/--preview/审计；create 收
显式条件句——生成走 agent 自己的模型而非后台客户端，诚实记录此缝）；
`ai cold <key>` 读 0003 的已存裁决（非 CLI 现场调用）；eval：确定性场景
离线（夹具补全注入客户端缝），裁决器场景走活体门；
`ASTRA_LLM_NANO_BUDGET_MICROS` 裁决前检查。
- [ ] 测试先行：动词往返；preview 等值；审计行；eval 运行器确定性通过；
  护栏跳过路径。
- [ ] 实现；提交
  `feat: add rules verbs, the eval harness, and the spend guard`。

  后台客户端留在宿主侧）；eval 运行器需要客户端缝注入夹具补全（在
  LlmClient 上加仅夹具用的构造或 trait——T5 指名）；活体门的成本纪律
  （断言 token 数量级合理而非精确）。
