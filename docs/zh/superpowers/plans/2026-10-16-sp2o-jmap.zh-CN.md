# SP2o JMAP 账户实施计划

> **给代理工作者：** 必须使用 superpowers:subagent-driven-development（推荐）
> 或 superpowers:executing-plans 按任务逐条执行本计划。步骤使用复选框
> （`- [ ]`）语法跟踪。

**目标：** 端到端交付 JMAP 账户：一个秘密的配置与拨号、向导臂、宣告处的
OAuth 腿、对 harness 的密码腿实测、以及文档。

**架构：** astra-account 增长 `jmap/`（连接、URL 推导、OAuth 腿的刷新包
装器）；向导增长 JMAP 表单；引擎的 provider-jmap 在共享策略之后拨号。
**技术栈：** 现有工作区加 decision-4 条款下的 provider-jmap。
**规范：** `docs/superpowers/specs/2026-10-16-sp2o-jmap-design.md`

## 全局约束

- 各切片通用的内部规则：SPDX、500 行上限、deny-everything lint、提交前跑
  gate（直接退出码）、约定式提交、无破折号、英式英语、zh 镜像同提交、
  线协议只增。
- 常设指令：PR 合并即自动继续；SQUASH AND MERGE；10 分钟作者窗口。
- 令牌与秘密绝不入日志；Secret 纪律。引擎保持对 OAuth 一无所知。

### 任务 1：账户半边
**文件：** `crates/astra-account/src/jmap/{mod.rs, connect.rs}` + 测
试（[jmap] 节：一个秘密、遗留 token 读取、URL 推导矩阵；在共享 TLS/重
试之后装配 JmapProvider 的拨号；账户 id 推导 `address@jmap:<host>`）。
- [ ] 先写测试；提交 `feat: port the jmap account half`。

### 任务 2：刷新包装器 + OAuth 腿
**文件：** `crates/astra-account/src/jmap/{refreshing.rs, oauth.rs}` + 测
试（SP2l OAuthClient 之上的 RefreshingJmapProvider；只在服务器宣告时提
供的发现；四条约束；持久化的 [jmap.oauth]；从持久化授权的重新授权）。
- [ ] 先写测试；提交 `feat: port the jmap oauth leg`。

### 任务 3：向导臂 + 宿主接线
**文件：** 向导的 JMAP 表单（+ 测试：一个字段、推导 URL、宣告门控的
OAuth 提议、fail-soft）；桌面的添加/连接路径；类型行。
- [ ] 先写测试；提交 `feat: offer the jmap account in setup`。

### 任务 4：实测 + 文档
**文件：** 门控的 live 套件（对 harness JMAP 的密码腿端到端：连接、文件
夹、列表、正文、一次发送；宣告处的日历读；OAuth 发现的诚实钉或缺口）；
`docs/jmap.md` + zh；capabilities 行；fragment。
- [ ] 提交 `feat: prove the jmap account live and record it`。

### 任务 5：收尾
- [ ] 全量电池；推送分支 `sp2o-jmap`；PR（预期 squash）；分类账清理。

## 自评注记

- 规范覆盖：D1-D3（T1）、D4（T2）、D5/D6（T3）、实测 + 文档（T4）。
- 接口链：账户半边（T1）-> OAuth 腿（T2）-> 向导（T3）-> 实测 + 文档
  （T4）。
- 风险：遗留 token 读取的向后兼容（钉住它）；刷新包装器的重建纪律（棘
  轮式 JMAP 服务器是丢失轮换会杀死账户的唯一地方——Graph/Google 形态移
  植但 FASTMAIL 规则约束）；harness 的 OAuth 宣告（决定诚实的钉）；账
  户级文件夹绑定器（每个文件夹一个提供商——绑定器的 jmap 臂必须重连
  它，而非按文件夹铸造）。
