# SP2l OAuth 地基实施计划

> **给代理工作者：** 必须使用 superpowers:subagent-driven-development（推荐）
> 或 superpowers:executing-plans 按任务逐条执行本计划。步骤使用复选框
> （`- [ ]`）语法跟踪。

**目标：** 移植 OAuth 地基：纯 PKCE 客户端 crate、带深链重定向的系统浏
览器会话、含三条应答路径的凭据事务、带拒绝状态的向导骨架、发现的实测
证明、以及契约文档。

**架构：** `astra-oauth`（新 crate，移植自 mail-calendar 的
`mailcal-oauth`：纯函数、可测、不依赖引擎）拥有流程的纯半边；桌面宿主
拥有浏览器会话与 OS 密钥库；应用核心拥有事务的"何时"。
**技术栈：** 现有工作区加 `astra-oauth`（S256 与 state 用 MC 同款依赖；
移植同样的选择）；`tauri-plugin-deep-link`（已是依赖）。
**规范：** `docs/superpowers/specs/2026-10-13-sp2l-oauth-design.md`

## 全局约束

- 各切片通用的内部规则：SPDX、500 行上限、deny-everything lint、提交前跑
  gate（直接退出码）、约定式提交、无破折号、英式英语、zh 镜像同提交、
  线协议只增。
- 常设指令：PR 合并即自动继续；SQUASH AND MERGE；10 分钟作者窗口。
- 引擎对 OAuth 一无所知（只收 bearer 令牌）；OAuth 代码绝不漏进引擎。
  令牌绝不入日志；Debug 处处脱敏。

### 任务 1：crate 的预注册半边
**文件：** `crates/astra-oauth/src/{lib.rs, pkce.rs, token.rs, scopes.rs,
provider.rs, grant.rs}` + 移植的测试文件；crate 接线。
**移植：** S256 对 + state；exchange/refresh/TokenSet（refresh 绝不带作
用域；已授予缓存跟随响应）；提供商配置与作用域清单；GrantRefusal 的分
类。
- [ ] 先移植测试（它们就是契约）；实现；提交
  `feat: port the oauth client's registered half`。

### 任务 2：crate 的开放半边
**文件：** `crates/astra-oauth/src/{discovery.rs, register.rs,
credentials.rs, reach.rs, mail_providers.rs}` + 测试。
**移植：** RFC 9728 -> 8414 -> 7591；credentials 作为注册的唯一持有处；
传输分类；已知提供商表。
- [ ] 先写测试；提交 `feat: port the oauth discovery and registration`。

### 任务 3：宿主会话 + 凭据事务
**文件：** `client/desktop/src/oauth/{session.rs, transaction.rs}` + 测
试（深链捕获、原始 URL 交回、state 不匹配）；`AccountCredentialStore`
的 persist/delete 报告；脚本化存储驱动的三条应答路径（添加回滚、轮换
记录、移除报错）；scheme 在 tauri.conf.json 若尚未有。
- [ ] 先写测试；提交 `feat: host the browser session and the credential transaction`。

### 任务 4：向导骨架
**文件：** `client/web/src/features/account-setup/**`（注册存在时的
OAuth 提议）；拒绝语句；桌面命令（sign-in 的 begin/complete 对）；线协
议。
- [ ] 先写测试；提交 `feat: offer the provider sign-in in setup`。

### 任务 5：实测 + 文档
**文件：** 对 harness JMAP well-known 的门控发现证明；
`docs/provider-oauth.md` + zh（规则整体搬入，按现在交付 vs 提供商切片
裁剪）；capabilities 行（仅地基行：OAuth 脚手架行移动；Graph/Google 行
不动）；fragment；全量电池。
- [ ] 提交 `feat: prove the discovery live and record the oauth contract`。

### 任务 6：收尾
- [ ] 全量电池；推送分支 `sp2l-oauth`；PR（预期 squash）；验收证据；
  分类账清理。

## 自评注记

- 规范覆盖：D1（T1/T2）、D2（T3）、D3（T3）、D4（T4）、D5（T1 的令牌
  测试 + T3 的事务）、实测 + 文档（T5）。
- 接口链：crate 半边（T1/T2）-> 宿主会话与事务（T3）-> 向导（T4）->
  实测 + 文档（T5）。
- 风险：移植保真（MC 的测试就是契约：先移植它们，不是之后）；Windows
  的深链捕获（scheme 注册按构建；harness 证明 URL 形态，真实浏览器往返
  属 SP2m 的首次登录）；重放规则的单飞（移植的并发测试必须活着过移植）；
  credentials.rs 携带的 id 不是秘密但是构建输入（决定：不移植 MC 的真
  id：用 Astra 自己的注册，所有者注册应用前为占位；未给的构建仍能工
  作，这正是 crate 自身的契约）。
