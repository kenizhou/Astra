# 垃圾邮件拦截：Astra Mail 契约

**范围。** 静音一个发件人：拦截某发件人，使其邮件不再触发新邮件
通知。对每一个交付该动词的表面都有约束力。它只做通知抑制，这是
锁定的 kylins 参考的红线：拦截名单只驱动新邮件抑制，别无其他。
被拦截发件人的邮件仍落入收件箱。拦截名单是一个偏好字段；抑制是
既有新邮件队列闸门中的一条确定性支路，而非 AI 入站处理，因此没有
评测或管线版本提升。不改引擎，不新增存储。缺口在文末记录，绝不
静默。

**原则。** *拦截只静音，绝不归档。* 把邮件归档为垃圾邮件仍是 Junk
动词的职责。拦截名单不移动任何邮件、不改任何旗标；被拦截发件人的
邮件照常落入收件箱，只是安静地。下文的可选举报支路复用已交付的
垃圾邮件举报，其归档是举报自身的行为，而非拦截的行为。

## 拦截名单偏好

`Preferences` 上的 `blocked_senders: BTreeSet<String>` 字段
（`sender_names` 的模式，空时 `skip_serializing_if`），持有规范化的
裸地址。地址被规范化为小写、去空白，并从显示形式
（"Ada <ada@x.com>"）中提取 addr-spec，即 VIP 集合的
`normaliseAddress` 惯用法在核心侧的镜像，使同一发件人的每种拼写
都归一到同一个键。空白地址不存任何条目。

`BlockSender` 与 `UnblockSender` 是骑在共享 `set_setting` 设置器上
的 `SettingsIntent` 支路：地址原样跨线，核心在分派时规范化它，即
zone id 自身的纪律。拦截在设置块（`blocked_senders`）上应答，因此
表面通过既有设置线路读取它；没有新的 IPC 类型。空拦截名单不写
条目，即展开映射自身的规范化。拦截名单是设备本地的（偏好文件）；
它不漫游。

## 抑制闸门

新邮件队列在 arm 时刷新拦截集合，正如处理过程已经读取同步设置
那样，`qualifies` 在收件箱类与自有归档支路之外新增一条“发件人
未被拦截”支路。因此被拦截发件人既不触发操作系统通知、也不产生
历史行：宿主桥接抽取队列，闸门从未持有的行两个通道都到不了。

闸门保持两条不变量：

- **过滤器失败开放。** 拦截名单读取失败绝不抑制通知。偏好加载
  失败开放到默认值（空拦截名单），空集合未抑制任何邮件，因此
  不可读的文件不会静音任何邮件。
- **拦截优先于 VIP。** 拦截支路是一票绝对否决，没有任何绕过，即
  参考顺序。Astra 的 VIP 是 web 本地的视图状态，在本通道中不拥有
  任何通知绕过，因此该否决无需 VIP 例外；web 套件在 VIP 集合所在
  之处钉住标记与拦截的顺序。

闸门是确定性的新邮件通道，而非 AI 入站处理：抑制是一次偏好读取，
绝非模型判断，因此没有评测运行或管线版本提升骑在它上面。

## 表面

行菜单的“拦截发件人…”条目（单行；批量以原因禁用）在该行的
发件人之上打开一个独立的 `BlockSenderDialog`。对话框拦截该地址，
并提供一个可选的“同时将此会话举报为垃圾邮件”复选框，默认勾选，
仅在账户可举报时显示（垃圾邮件动词自身的可见性规则：提供商可
举报且树解析出垃圾邮件目标）。举报复用已交付的 `mark_junk` 动词。
拦截是持久行为，无论举报结果如何都成立：举报失败被记录，绝不
撤销拦截。取消与 Escape 不分派任何内容。

设置管理区列出被拦截的发件人，每个带一个解除拦截，读取设置
线路。它落在 General 类别、新邮件通知开关旁边：Astra 没有“邮件”
设置类别，而拦截名单治理到达邮件如何自我宣告，是一种应用级行为。
该区明言被拦截邮件仍到达收件箱。

## 已知缺口

- **只做抑制。** 被拦截发件人的邮件仍落入收件箱；自动归档到
  Junk 是一个命名的非目标（参考红线；归档仍是 Junk 动词的职责）。
  自动归档将是一个独立、更具侵入性的切片。
- **设备本地。** 拦截名单是偏好文件；它不跨设备漫游，CLI 也不
  共享它（稍后处理/提醒的先例）。
- **无 CLI 动词。** 拦截名单是表面读取与写入的偏好（VIP/置顶的
  先例，偏好之上的纯视图状态）；不交付新的 CLI 动词。
- **设置类别。** 管理区落在 General，一个既有类别，因为 Astra
  没有“邮件”类别；一个表面细节，已记录。
