# 日志与诊断：Astra Mail 契约

**范围。** 窗口化运行的生产文件日志、每行都遵守的日志契约，以及
渲染、复制与导出它的诊断设置分类。对每一个以产品名义打日志的表面、
每一个交付诊断视图的宿主形态都有约束力。无头运行器保留自己的
stderr 日志器，不在本契约范围内。

**原则。** *起不来的诊断绝不为此拖垮应用。* 日志器尽力打开，打不开
的文件让本次运行保持无日志，原因落在 stderr；拒绝的轮转让日志器
保持熄灭。诊断观察产品，绝不把关产品。

## 文件日志

窗口化宿主在启动时安装轮转文件日志，早于启动流程自身的任何一行：
应用数据目录中的 `astra.log`，与各存储并列。它是手写的，是无头
运行器 stderr 日志器的姊妹件，因为诊断不拖任何日志框架进场。

- **轮转。** 最多五个文件站立：当前的 `astra.log`，加上
  `astra.log.1` 到 `astra.log.4`。当前文件已有内容且下一行会把它
  越过 1 MiB 时，轮转移动：句柄先关（Windows 拒绝重命名打开中的
  文件），最旧的轮转文件离去，其余上移一个编号，当前文件变成
  `.1`，新的当前文件打开并以轮转提示为第一行。一个多话的运行
  最多花费磁盘五个 MiB，绝不超过。
- **行形状。** 一行是纪元戳、级别词，然后是消息：
  `1792848440 INFO: boot: the app core is up over 2 account(s)`。
  戳是标准时钟的 unix 秒。
- **级别。** 级别在安装时从持久的调试偏好读取：诊断开关未立时为
  info，立起时为 debug。偏好直接从偏好文件读取，因为核心自己的
  副本要到装配之后才站立，而装配本身就要打日志。因此改动随下一次
  启动落地，开关下方的注释如实陈述：*takes effect the next time
  Astra Mail starts*（下次启动 Astra Mail 时生效）。
- **一个进程只有一次安装。** 日志器为进程的生命周期安装；已安装的
  日志器保持为本次运行所保留的那个。

## 日志契约

无秘密、无邮件内容、无仓库路径：这是代码库既有的契约，从文件第一
行起保持。日志器自己的行（安装提示、轮转提示）不携带任何一类，
每个宿主调用点遵守同一纪律。契约在真实启动自己写下的字节上实证：
证明在真实启动写入的文件上检索秘密标记（`password`、`secret`、
`token`、`bearer`）、邮件地址、仓库路径形状、路径分隔符与盘符，
任何一类都不得越过。

## 诊断分类

设置屏的诊断页渲染日志及其控件，每个控件反映拉取到的真相，绝不
本地乐观：

- **查看器。** Read 按钮经宿主的 `log_tail` 命令拉取当前文件的最后
  若干行，默认一屏（200 行），等宽渲染，最新在后。尾部把失控的
  请求钳在 1000 行，文件不足所求时应答整个文件，无文件时应答空。
  除行自身外没有路径越过。
- **复制以供支持。** 复制取尾部（查看器为空时现拉），旁边加上版本
  行；控件下方的隐私注记点名日志永不携带的东西：*The log carries
  no message content, no credentials, and no file paths.*
- **导出。** 导出让宿主的保存对话框以日志自己的名字（`astra.log`）
  打开整个当前文件，写入其逐字节内容，并应答附件保存同族的分型
  结果：带路径的 saved、cancelled、带原因的 failed。取消的对话框
  不写任何东西；读取失败根本不开对话框。
- **调试开关。** 持久的开关，其改动随下一次启动落地，注释如实
  陈述。

导出经分析记录器记录自己的产品事件（带字节计数的 `log_exported`），
因此该事件只在同意站立时落账（analytics.md）。

## 已知缺口

- 日志器没有 trace 级别，也没有按目标的过滤：只有 info 与 debug
  两个级别、一个开关。
- 尾部只渲染当前文件；轮转文件归导出与磁盘自己管。
