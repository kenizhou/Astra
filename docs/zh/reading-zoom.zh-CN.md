# 阅读缩放与重排：Astra Mail 契约

**范围。** 阅读正文的缩放档位与固定宽度重排，对每一个渲染邮件正文
的表面都有约束力。缺口在文末记录，绝不静默。

**原则。** *正文的文档属于读者。* 消毒后的片段从不裸渲染：它乘坐
应用自己拥有的包装文档，其基础字号是当前的缩放档位，其 viewport
meta 是发件人移动端规则所读的，其钳制规则把每个固定宽度的元素
约束在框内。

## 三个档位

Smaller、Default、Larger：13、16、20 像素的基础字号，与应用字号相同
的三档形状，控制器位于阅读信头，按读者跟踪，存于本地外观存储中
字号档位的旁边（设备偏好，绝不是跨账户的邮件偏好）。默认值是框
文档自身的中号，即十六像素，因此既有的默认档位不改变正文原本的
渲染。

## 包装文档

消毒后的 html 乘坐 srcdoc iframe，包裹在阅读缩放自己的文档中：

- **viewport meta**（`width=device-width, initial-scale=1`）让发件人的
  移动端规则读到框的宽度，因此按阅读窗格自身宽度排版的 newsletter
  在每个宽度上都应用其自身规则。
- **基础字号**随当前档位缩放；消毒后的片段逐字乘坐包装文档的
  body，快照与框之间没有任何转义或改写。
- **钳制**把固定宽度的内容约束在视口内：对 body 的直接子元素以及对
  `img`、`video`、`table` 施加 `max-width:100% !important`，`img` 与
  `video` 的高度随之重排，因此硬像素宽度的表格被约束在框内，正文
  文本在调整大小的过程中实时重排。这些规则是 CSS，浏览器在每次
  布局遍历时重新应用；不运行任何脚本，也不做任何重新折行。

## 纯文本半边

纯文本正文按相同的档位与相同的三个数值缩放，因此一个控件移动
每一封邮件。统一两个半边把纯文本正文的默认值从 13px 移到 16px，
即框文档自身的中号。

## 已知缺口

- 档位是三个，与应用字号档位一致；不提供自由百分比。
