# 旗标提醒：Astra Mail 契约

**范围。** 请求稍后提醒某条消息：在一条消息上选一个唤醒时间，到唤醒
时刻用户会收到通知。消息不移动，也不自动加旗标（既有的 Flag 动词保持
独立）。对每一个交付该动词的表面都有约束力。引擎没有提醒机制，因此
这是一个宿主/核心特性：一个设备本地的提醒存储、一个宿主唤醒定时器、
以及一个提醒通知事件。不改引擎。缺口在文末记录，绝不静默。

**原则。** *消息留在原处，因此提供商标键保持有效。* 提醒绝不移动邮件，
绝不触碰未读计数；它不拥有任何引擎状态。因为消息从不移动，设置时记录
的提供商标键保持为有效链接，唤醒无需同步、也无需按 Message-ID 重新
解析（稍后处理存储的重新解析机制在此按设计缺席）。主题与发件人在设置
时捕获，因此唤醒构建通知时无需读取引擎。

## 存储

新 crate `astra-reminders` 持有日程（AI 账本存储的形状：一个互斥锁下的
rusqlite 连接、在事务中认领的嵌入式迁移、五秒忙超时、供测试用的内存
打开）。宿主在数据目录打开 `reminders.sqlite` 并安装到核心（analytics
的安装形状，一个 `Mutex<Option<Arc<Store>>>` 槽；无 `AppState` 字段，
因此 drop 顺序保持原样）。每条提醒一行：

- `account_id`，所属账户（新类型 `AccountId`）。
- `provider_key`，设置时的键（新类型 `ProviderKey`），唤醒打开该行所凭
  的链接；它保持有效，因为消息从不移动。
- `wake_at`，唤醒时刻，unix 秒。
- `subject` 与 `sender`，设置时捕获，供唤醒的通知使用。
- `created_at`，存储自己的时间戳；`wake_at` 上的索引。

没有 `origin_folder`，也没有 `message_id`：两者都不适用，因为消息从不
移动。方法为 `record`、`due(now)`（`wake_at <= now`，最早优先）、
`remove` 与 `list`。身份无法解析的行被跳过，绝不致命于读取它的批次。
存储是设备本地的：不跨设备漫游，CLI 也不共享它（宿主定时器特性，稍后
处理的先例）。

## 核心提醒与唤醒

`remind_message(row, wake_at)` 拒绝会话行（提醒命名单条消息），从引擎
自己的副本读取消息的提供商标键、主题与发件人，并记录条目。不移动，
不加旗标编辑。

`wake_due_reminders(now)` 读取到期条目，对每一条构建一个
`NewMailNotice`（账户、提供商标键、以及设置时捕获的主题与发件人，复用
新邮件载荷因此 wire 形状一致），移除条目，并应答通知。无同步、无重新
解析、无移动、无表面重新发布。坏行被到期读取跳过，绝不滞留批次。主体
是同步的（它读取存储并构建通知，无引擎调用）；宿主的端口将其包装进
定时器驱动的异步滴答。

## 唤醒定时器

宿主 `reminder_timer`（稍后处理定时器的形状）每分钟滴答，读取存储的
到期条目，通过 `AppPort` 调用唤醒主体，并经通知桥投递通知。它在存储
之上无状态，因此重启会重新读取到期条目。间隔与滴答上限可调试覆盖
（`ASTRA_REMINDER_SECONDS`、`ASTRA_REMINDER_LIMIT`）以供确定性运行；
发布构建保持常备节奏且永不停止。定时器持有三个 `Arc`（核心、存储与
桥），因此 `AppState` 的 drop 顺序不受影响。桥由拥有窗口句柄的调用方
构建一次并传入 `assemble_state`（窗口宿主构建 `windowed`，无头宿主
构建 `logged`），与投递循环共享。

## 提醒通知

`NotifyBridge::deliver_reminders(batch, enabled)` 尊重
`notifications_enabled` 开关，为每条到期提醒显示一条标题为 "Reminder"
的操作系统通知（正文为捕获的主题），并在 `reminder` 事件上发出
`NewMailBatch` 载荷（overflow 为零）。没有焦点抑制：明确的用户请求在
窗口聚焦时也触发，enabled 开关是唯一的门（Astra 没有勿扰设置）。历史
通道失败被记录、绝不上抛，因此它无法抑制已经发出的操作系统通知。
web 的 `reminderFlow` 与 `reminderEvents` 将每次落地记录进新邮件挂载
所喂的同一通知历史；历史面板无需改动（条目携带账户与键，因此点击打开
照常工作）。

## 表面

行菜单的 "Remind me…" 条目（单条消息；会话或批量附带原因禁用）打开
一个选择器，提供今天晚些、明天、下周作为计算出的时刻。选择器复用稍后
处理的预设算法（`services/snooze.ts` 的 `snoozeChoices`）；这些标签对
提醒而言读起来也正确。选择一个即触发宿主的 `remind_message` 命令并
关闭；Cancel 与 Escape 不派发任何内容。wire 走 `services/reminders.ts`
（绝不走 `ipc.ts`，它已到上限）；桌面命令位于 `commands/reminders.rs`
子模块（`commands.rs` 已到上限）。

## 参考偏差，已升级

锁定的 kylins 参考（Follow Up 族）将到期旗标保持为持久：行保留直到
用户清除它，一个徽标标记该线程，一个仅一次的前端门触发提示一次。本
切片交付更小的唤醒即移除生命周期（稍后处理的先例）：条目在触发时被
移除。没有徽标表面的持久行是不可见的死重；使持久有意义的徽标表面是
第二个切片。这是对参考生命周期的有意偏差，在此与 PR 中升级，而非
静默。参考的红线得到遵守：提醒绝不移动邮件，绝不触碰未读计数，不拥有
引擎状态。

## 关闭应用期间的唤醒精度

定时器仅在进程存活时运行。关闭应用期间到期的唤醒在下次启动触发，而非
精确时刻：桌面宿主定时器的固有特性，记录而非隐藏。

## 已知缺口

- **kylins 对齐生命周期**（持久到期标记与徽标、Clear reminder 动词、
  upsert 重设使重新加旗标移动截止时间、以及仅一次的提示门）是已升级
  偏差的后续。
- **设备本地**：提醒存储不跨设备漫游。
- **关闭应用期间的唤醒精度**：关闭应用期间到期的唤醒在下次启动触发，
  而非精确时刻。
- **自定义唤醒时间**、会话与批量提醒、ribbon 或面板入口、以及 CLI/agent
  动词是后续。
- **过期打开链接**：若消息在唤醒前被移动或删除（v1 无 Message-ID 重新
  解析；与新邮件通知携带的相同暴露）。
- **无摘要折叠**：当许多提醒同时到期时；无勿扰设置。
