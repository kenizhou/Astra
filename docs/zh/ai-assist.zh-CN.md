# AI 辅助：Astra Mail 契约

**范围。** A1/A2 基础上的 A3 辅助能力：带批量抽取与草稿提示词
知识上下文的知识库、带排序搜索与编写器选择器的片段库、带悬浮条的
编写自动补全建议、带缓存的翻译动作，以及暴露它们的宿主命令与 CLI
动词。约束每一个交付其中任一能力的界面（目前是桌面宿主、网页编写器
与阅读窗格、`astra-cli`）。

**原则。** *辅助能力帮助写信人；绝不独自行动。* 知识是关于账户主人
的模型衍生数据，始终作为数据保存，绝不作为指令；片段是写信人自己的
文本，整段保存且只落在光标所在处；自动补全建议绝不在写信人手势之外
插入；翻译渲染在原文旁边，绝不取而代之。这里没有任何东西会发送邮件，
模型侧的运行都住在应用里：CLI 读取存储并拒绝模型类拼写（永不拨号
规则，见 `docs/cli.md`）。

## 知识

每条抽取的条目一行（`ai.sqlite` 迁移 `0007`）：条目所属的账户、
类别、文本、来源对（被抽取邮件的账户与提供者键）、抽取回合的关联
id、库自盖的时间戳。**类别封闭集**是 `fact`、`preference`、
`project`、`contact`、`persona`；补全里的未知类别词让整次解析响亮
失败（整批什么都不落，绝不猜），已入库的外来词在列表里按原样透过。

**账户拥有自己的知识。** 条目属于被抽取邮件的账户：抽取拉取读一个
账户，条目落在这个账户名下，草稿提示词只读自己账户的条目。任何东西
都不跨账户共享知识，这是有意为之（风格档案自己的框架）。

**抽取**是一个批任务（`KNOWLEDGE_EXTRACT_VERSION`，economy 层）：
宿主命令 `knowledge_extract(account, limit)` 收集账户最新的邮件，
新者在前，以 `KNOWLEDGE_EXTRACT_LIMIT`（30）封顶。上限住在命令
边界：缺省的 limit 以三十穿过，超过三十的具名 limit 也以三十穿过，
因为窗口读取会为每条消息花一次正文抓取，而服务侧的批次守卫随后就会
把它们丢掉。每条邮件以自己的非受信包裹进入唯一批次提示词，挂在受信
的 `Message N:` 标签下，旧者在前，正文以 `KNOWLEDGE_BODY_CAP`
（2000）字符封顶并带截断标记。补全指明每条条目取自哪封邮件，落库行
因此保住来源；越出批次的引用只丢弃它自己的条目。失败的调用或不可
解析的补全什么都不落并记录日志；命令返回本次运行的摘要
（`extracted`、`skipped_duplicates`、`messages_considered`），其零值
诚实地说明失败。

**精确文本去重守卫。** 存储在 (account, text) 上的唯一索引拒绝为
账户已持有的文本再落一行，重复抽取绝不堆叠条目：插入循环安静跳过
拒绝，摘要把它计入。**条目绝不自动删除**；`knowledge_forget(id)`
是唯一出口，宿主命令与 CLI 动词一样。

**草稿提示词的知识上下文。** `knowledge_context(account)` 读账户的
条目，把最新的 `KNOWLEDGE_CONTEXT_LIMIT`（10）条各渲染成一行
`kind: text`，顺序是 persona 最前、preference 随后、fact、project、
contact 一样按新近排后（类别相关序）。这些行作为**标注数据**走草稿
提示词的受信半区，是 `DRAFT_REPLY_PROMPT_VERSION` 2 的 A3 一半：
基于非受信邮件的模型衍生文本绝不能冒充指令。读取失败就什么都不答，
草稿宁可没有知识也不因塑形失败。

## 片段

每个片段一行（`0008`）：标题、正文、库自盖的创建与触碰时间戳。
标题与正文是写信人自己的文字，绝非模型衍生，像风格笔记与规则条件
一样不经包裹进提示词。片段库是所有界面共享的唯一存储：CLI 的
agent 优先 CRUD（`snippets list`、`snippets create` 取 `--title`
与 `--body` 或 `--body-file` 恰好其一、`snippets delete`，每个
变更动词带 `--preview`）与编写器选择器。**替换语义**：片段在它的
身份下只有一行；更新就地重写标题与正文并触碰 `updated_at`，新近
优先的列表排序就骑在这个时间戳上，被编辑的片段重新浮到最前，任何
编辑都不长出第二行。尚无界面调用 `update_snippet`：存储已备好，
宿主命令与 CLI 动词都没有它的拼写。

**排序搜索**（`SNIPPET_SEARCH_VERSION`，economy 层）是针对整个
片段库的一次结构化补全：提示词给片段编号，要求按顺序回答匹配的
**位置**，最佳在前。线上走的是位置而不是 id：被模型抄歪的长 id 会
无声地损失匹配，而位置是提示词自己刚报过的一位数字。越界或重复的
位置只跳过自己。**子串回退**：失败的调用或解析与修复都救不回的
输出，回退到对标题与正文的忽略大小写子串搜索，按片段库自身顺序；
空库不调用直接答空；可解析的排序（包括空匹配表）被当作已回答
（诚实的无匹配，绝不回退）。

**编写器选择器**按最近触碰在前列出片段库，每次挂载拉取一次，搜索
框修剪过的查询经 300ms 防抖送到 `snippet_search`；清空查询退回普通
列表且不调用。选中的行把正文交给插入接缝，插入接缝把它按纯文本放到
光标处（一行内联进当前段落，后续行各成段落），正文的换行得以保留，
任何片段都夹带不进 HTML 标记。

## 自动补全

`compose_autocomplete(before, after)`（`AUTOCOMPLETE_VERSION`，
chat 层以换延迟）回答一段简短续写，延迟路径上没有 JSON：补全修剪后
作答，提示词把光标两侧的编写器文本放在两个标注的半区里，各自进入
自己的非受信包裹（文本可能引用邮件），光标在末尾时省略后半区的块。
失败的调用答空字符串，悬浮条不出现。

**永远只在手势下。** 编辑器把建议渲染成锚在当前行下方的暗色悬浮
条，在停止输入两秒后武装（每次击键重开窗口），空编写器或与上次
询问相同的上下文跳过。插入**绝不**在没有手势时发生：Tab 或点击
建议，都走选择器共享的唯一插入接缝。**关闭**（悬浮条的 X）在本
会话余下时间藏起悬浮条：直到下一次编写让悬浮条重新挂载，不再武装
任何询问。接受的插入会触发编写器的 update，在新的上下文上武装
新的空闲窗口（Copilot 式循环）；关闭即停。

## 翻译

`translate(account, key, lang)`（`TRANSLATE_VERSION`，default 层）
把打开邮件的正文渲染成固定六语言之一（默认英语，另有中文、德语、
法语、日语、西班牙语；线上词为 snake_case），正文整段非受信包裹，
目标语言在受信半区点名。答案在窗格里渲染成摘要旁边的可折叠块，
以自己的语言标注。

**缓存**（`0009`）以（邮件账户、邮件键、类别 `translate`、目标
语言、正文哈希）为键，一键一行：同一语言的新正文哈希替换该行
（一键一行的替换语义），不同语言各持自己的行。命中**不**发起任何
模型调用、不新增账本行（正文解析仍花一次引擎抓取）；阅读窗格的
重新展开即时读取。失败方向是假性未命中，
绝不是过期命中：失败或不可解析的调用什么都不缓存。

**空答案即错误状态。** 线上对无法再解析的邮件与失败的调用都答空
字符串，所以翻译块把空当作无名失败，给出自己的句子并保留原有的
Translate 动作作为重试；被拒绝的运行以同样方式给出自己的句子。
未来的线上协议可能想把失败点名而不是清空；作为缺口记录在下面。

## 永不拨号规则与 CLI

CLI 读取存储且绝不拨号模型：`knowledge list`（每条带其来源对）、
带 `--preview` 的 `knowledge forget`、`snippets list`、带
`--preview` 的 `snippets create`、带 `--preview` 的 `snippets
delete`。模型类拼写解析后拒绝（退出码 3，账本行记录拒绝）：
`knowledge extract` 与 `snippets search` 点名规则并指向应用，是
`ai style rebuild` 的先例。自动补全与翻译根本没有 CLI 拼写；它们
是编写器与阅读窗格的手势。完整的动词行与拒绝句子见 `docs/cli.md`。

## 评测钉与实机证明

四份提示词经评测工具钉住常量（`evals/`，任务 3 的夹具）：
`KNOWLEDGE_EXTRACT_VERSION`（两条带引用的来源条目）、
`SNIPPET_SEARCH_VERSION`（排序顺序）、`AUTOCOMPLETE_VERSION`
（续写）、`TRANSLATE_VERSION`（缓存的第二次读取），草稿升级到
`DRAFT_REPLY_PROMPT_VERSION` 2 随草稿夹具走。离线电池在 CI 跑
它们。

门控实机套件（`client/desktop/src/ai/live_assist_tests.rs`，在
`ASTRA_LIVE_LLM=1` 下，抽取另需 `ASTRA_LIVE_HARNESS=1`，对着运行中
的 Stalwart 测试台，一次一个测试）在真实接缝上证明各服务：对测试台
账户最近邮件的一次真实抽取（种子笔记旁边是证明自发的持久笔记；条目
带着来源落库，类别在封闭集内，摘要计数与存储及账户邮件数交叉核对，
economy 层账本行令牌合理，事后清场撤回证明自己的邮件）、对种子片段
库的一次真实排序（查询与任何标题正文都无子串重合，只有排序答案可能
非空，被问到的片段排最前）、chat 层下的一次真实自动补全续写、以及
一次网络调用答两次的真实翻译，账本行计数就是无请求的证明。

## 已知缺口

- **悬浮条的 Tab 处理是文档级的。** 建议悬着时，无论焦点在哪，
  Tab 都接受它，这是本意；未来在编写器内自带 Tab 处理的界面可能
  想把处理器限定到编辑器自己的键表。
- **悬浮条的未变文本跳过是单槽记忆。** 只记住上次询问的上下文：
  回到两次询问之前的上下文会重新询问。这是规格的措辞（未变文本
  跳过）与便宜的守卫；历史记录会为没有观察到的需求无限增长。
- **选择器分不清失败的列表与空片段库。** 两者都以同样安静的空
  面板加同一句提示作答（失败的拉取记录日志并答空）；管理片段库
  的设置界面可能想要点名失败。
- **自动补全的两个半区不经上限穿过。** 光标前后的文本整段进提示
  词；一份非常大的编写会变成一次非常大的询问。上限会从半个上下
  文里无声地建议；若实机成本需要，应作规格决策。
- **翻译正文整段穿过。** 截断上限会无声地只翻译半封邮件，比大
  提示词更糟；同样的规格决策框架适用于成本需要时。
- **去重识别匹配错误文本。** 抽取循环凭 `UNIQUE constraint
  failed` 的消息文本识别存储的拒绝，知识表上另一种唯一违规也会被
  安静跳过；在今天的模式下可忽略，类型化错误可以关掉它。
- **排序搜索提示词无上限。** 每次搜索都携带整个片段库；长到几百
  条的库会想要列表上限或调用侧的预过滤。规格未钉上限，所以没有
  凭空发明。
