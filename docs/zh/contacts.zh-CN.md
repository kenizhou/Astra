# 联系人：Astra Mail 契约

**范围。** People 视图展示什么，如何把一个人与被归档为他们的卡片区
分开，联系人写入可以做与不可以做什么，编写器的收件人补全从哪里取
答案，以及账户的联系人腿如何拨号。对每一个交付 people 视图或收件人
字段的表面都有约束力。实质移植自 mail-calendar 的 `contacts.md`，按
Astra Mail 今日交付的范围裁剪；缺口在文末记录，绝不静默。

**原则。** *通讯录是卡片列表，不是人员列表。* 谁是一个人由引擎决
定；每个表面渲染这一决定并予以披露，而写入绝不越过两者之间的边界。

## 谁是一个人由引擎决定

同一个人常常被归档在多个账户的多个通讯录里，所以引擎从卡片推导出
统一的人，每个表面渲染的是人，绝不是卡片。连接刻意收窄：

| 连接依据 | 绝不连接依据 |
|---|---|
| 一个共享的规范电子邮件地址 | 姓名 |
| | 电话号码 |
| | 组织 |

**姓名绝不连接，这是规则承重的那一半。** 两个不同的人常会同名，而
合并对用户的理解是破坏性的：他们归档了两位同事，现在只看到一个，
一组细节悄悄胜出。漏掉一次合并只是外观上的烦恼；错误的合并会藏起
一个人。这一不对称正是连接保守而非聪明的原因，也是任何表面不得在
其上自行添加匹配的原因。

### 合并必附说明

- 只要一个人来自多于一个账户，列表行就显示 **In N accounts**。计数
  是该人来源跨越的不同账户数，在快照中统计一次；宿主绝不重算，一个
  人归档在同一账户的两个通讯录里仍然只算一个账户。
- **绝不显示 In 1 accounts。** 它在每个普通联系人身上都是噪音，还是
  不合语法的噪音；没有合并要披露时，计数不越过任何键。
- 详情在 **Also in** 之下点名来源，并为每个值标注供给它的卡片：这个
  地址在你的工作账户，那个两边都有。

### 已退役的人员 id 仍然可解析

合并会退役 id，而引擎让退役的 id 指向幸存者，所以后台刷新合并之后
表面仍持有的行仍然可以打开。用列表铸造的 id 发起 `OpenPerson` 从不
需要先刷新列表，解析为无人的详情意味着这个人真的不在了，绝不是仅仅
改了编号。

## 折叠与徽标：重建中的一次推导

引擎的页按小写显示字符串的原始码点排序，且钉定修订的引擎不携带
分节或头像模型。因此呈现事实**在应用的重建中一次性推导**，所有表面
共享：这是对移植契约的已记录偏差，后者把同样的推导放在
mail-calendar 的核心里。

- **分节折叠。** 一个字母表，带音符的字母归入其基础字母（Émile 归
  E，落在 Emil 与 Emma 之间；Øystein 归 O），其后一个 `#` 桶收纳所
  有不以拉丁字母开头的内容：数字、符号，以及其他所有文字系统。折叠
  覆盖 Latin-1 Supplement 与 Latin Extended-A，即欧洲通讯录会持有的
  变音符；把西里尔或 CJK 姓名折叠成不是它的拉丁字母比不说话更糟。
- **折叠排序列表，而不是页。** 重建在发布前按自己的折叠键重排页内
  的行，因为引擎的排序与折叠的分节否则会不一致：原始码点把 Émile
  排在 Emma 之后，而按页序排布的分节列表会让 E 区持有越过其字母的
  行。行绝不被重新过滤：引擎对每个人匹配查询，宿主在页上过滤会悄
  悄找不到任何已被页上限截断的人。
- **徽标。** 首字母取姓名第一个词与最后一个词的首字符，大写且其余
  不动（Émile 保留他的 É）；来源没有姓名时取地址首字符；两者皆无时
  为空，即宿主绘制自己的人员图标的信号。底色来自钉定的八色板，按小
  写主地址取键，因此每人稳定，人员 id 作为后备键：一个人不能在不同
  表面之间换颜色，同色的两个人仍以首字母相区别。

同一推导站在快照的行、详情与宿主的头像命令之后，所以同一个人不会
在一个屏幕上是 `AL` 而另一个屏幕上是 `A`。

### 姓名或信号，绝不是占位词

一张卡片合法地只带地址不带姓名。这样的人的行显示名**为空**，绝不是
占位词：宿主用用户的语言补上措辞，而折叠与徽标仍按引擎选择的身份
（地址）取键。核心发明的占位词只能是英语。

## 写入点名卡片，绝不只点名人员

联系人可以创建与编辑。不提供删除（见文末缺口）。People 视图上的其
他一切都关于人，而写入不是：引擎把多个账户的卡片连接成一个人，不
选其中一张卡就保存屏幕上的值，会把工作账户的细节归进个人账户的通
讯录，而结果看起来完全正确。

- **编辑同时携带人员、账户与卡片。** 人员随行，使合并期间持有的行
  仍可解析；账户与卡片才是写入真正去的地方。
- **编辑器从卡片播种**，经引擎的存储卡片读取，绝不是用户刚在看
  的合并详情。合并者的地址属于不同的卡片，把它们全部提供为保存进
  一张卡是同一错误的另一种形式。
- **有多张卡时表面询问选哪张**，并点名账户。一张卡直接进入表单。

### 两个入口都是条件性的，各回答一个问题

| 入口 | 显示时机 | 因为 |
|---|---|---|
| 创建 | 快照的创建目标非空 | 目标是可写通讯录；目录或只读共享簿是联系人的来源地，提供它会得到用户全部输完之后在服务器失败的保存 |
| 编辑 | 详情的可编辑卡片非空 | 同一规则，按人 |

没有可编辑卡片的人要用原话说明，而不是留给用户从缺失推断，或按一
个按两次就开始怀疑的禁用铅笔去猜。

### 编辑不得破坏什么

卡片携带的远多于编辑器展示的，而编辑让它们全部保持原样：

- **patch 只点名变化的字段。** 编辑点名的每个字段都被替换，而由表
  单构建的替换会丢掉表单无法展示的一切：地址的语境、组织的单元、
  属性自己的标识符。变化的字段在卡片已有属性**之上**重建，元数据
  原样随行，未变化的字段完全省略。什么都没改的编辑什么也不发送。
- **有姓氏时才写结构化姓名。** 卡片合法地只带格式化姓名而没有结构
  化姓名，编辑器播种这样的卡片时把整个姓名放进名字字段。由此发射
  组件会把 Ada Lovelace 归档为没有姓氏的名字，写进用户拥有的其他
  每个客户端，而这是一次什么都没改的保存。

地址的顺序就是卡片上的顺序，因为第一个是此人的主地址：头像颜色与
列表行取键的依据。

### 卡片必须可再找到

创建除非点名可归档依据（姓名、组织或地址）否则被拒绝。格式化姓名
由存在者中的第一个推导，所以公司联系人读作其公司而不是空行。

### 状态的含义

- **`FailedWithRetry` 不表示被拒绝。** 服务器调用成功但写后和解未
  落定的写入**已到达服务器**；只是本地副本短暂过时，下次刷新执行的
  重读会治愈它。表面说我们无法确认这次保存。
- **`Invalid` 是另一句话。** 核心在发送任何东西之前拒绝了表单，所
  以有要修正的东西，原样重试会被同样拒绝。表面把它写在用户仍在
  看的表单之下，而不是别处。
- **`Writing` 与 `FailedWithRetry` 渲染在列表旁**，绝不在详情面板
  内：创建是在没有人打开时进行的，画在那里的线是刚创建联系人的用
  户读不到的。

## 自动补全

编写器收件人自动补全取用同一个人员索引，但不以联系人为门控：引擎
在普通同步期间从每个账户的发件邮件挖掘收件人历史，所以完全没有通
讯录的账户（大多数账户）也能补全。只来自发件历史的建议与来自已保
存卡片的建议同样有效；快照区分两者，绝不隐藏只有历史的建议，它们
通常最有用。

**令牌，不是字段。** 编写器交给读取的是字段中最后一个逗号之后的文
本，绝不是整个字段：字段用一个字符串持有列表，整字段查询在输入了
第一个收件人后就什么都找不到。空令牌返回空；字段一获焦点就下拉用
户发过信的每个人，是噪音而不是帮助。

**地址裸插入**，不作为 `Name <address>`：引擎解析地址，显示名不给
它使用的任何东西添加价值，而含逗号的姓名会分裂成两个无效收件人，
用户直到发送失败才会发现。

**完成的收件人是药丸；正在输入的是文本。** 用户看作一个收件人的与
补全看作一个收件人的不能不一致，而一墙逗号分隔的地址没有提供可点
按移除错误地址的东西。字段的值保持**一个逗号分隔的字符串**：药丸是
它的视图，绝不是第二真相源，所以屏幕上不会出现不会被发送的东西。
每个药丸携带自己的移除控件。

**预填字段没有进行中的输入。** 调用者提供的每个地址都是完成的，所
以字段在播种那一刻被规范化为该形态，每个地址渲染为自己的药丸：回
复的推导收件人若保持原样，会画出一个药丸旁边散着一个地址，看起来
像丢掉了它实际持有的人。规范化播种，而不是一帧之后重写字段（打开
后的重写会被当作编辑），询问是否输入过任何内容时与规范化后的开栏
值比较。

**程序化变更后插入符去末尾**，所以下一个按键绝不落在刚插入的地址
里；编写器在新邮件上把插入符开在 **To**，已编址时开在**正文**：一个
谓词，不是两个可能不一致的标志。

**列表悬浮；绝不排挤其后的内容。** 它不占布局空间，所以 Subject、
编辑器与 Send 不会在用户输入第一个收件人时跳动；它不透明、不抢焦
点（它补全的按键持续到达）、屏幕上只有聚焦字段的列表，并且它遮住
编辑器（工具包会乐于把它自己的绘制合成在 web view 之上）。

**排序是引擎的**，原样传递：先是精确地址，然后前缀，然后子串，每
一层再按已保存性、新近度与发件历史计数落定。重新排序列表的表面会
种下自己的覆灭。

## 头像

人的头像先是上面的徽标，一次性推导，照片到来后替换。照片从引擎的
**缓存**联系人照片存储读取（填充缓存是后台趟的事，所以一屏陌生人
不花费提供商往返），并且只经宿主校验过的照片命令进入 web view：该
命令只为引擎自己联系人照片区内的路径提供 data URI，web view 绝不读
文件系统，也没有照片路径作为 URL 越过，浏览器不会被指到别处。
`avatars.md` 拥有整个头像契约：列在哪个表面立于何处（含邮件列表
行）、缓存与代价说明。

## DAV 腿

账户的联系人（与日历）经其存储配置的可选 `[dav]` 节到达，两条腿都
拨该节：

- **该节**点名 CalDAV 源，以及（当独立存在时）CardDAV 源，附两条腿
  呈送的登录。CardDAV 腿在该节未给出自己的源时回退到 CalDAV 源，因
  为几乎每个讲一种 DAV 方言的服务器都在同一源讲两种。两源皆无的节
  在加载时拒绝：悄悄丢了源的存储账户是要暴露的缺陷，不是悄悄永不
  同步的联系人列表。
- **启动拨号**在邮件拨号旁经真实的 `connect_dav_providers` 运行两条
  腿：CalDAV 提供商追加在账户的邮件提供商之后（日历路径按能力选中
  它），CardDAV 腿经 `install_contacts` 安装在账户旁。两腿独立拨号，
  失败的拨号只损失自己的腿并记录日志：账户保留邮件半边，启动继续。
- 发现是引擎的：适配器在自己的 connect 内解析 well-known 路径及其
  后的家。

两条腿都已对 harness 实测（见下）。

## 隐私

联系人是应用持有的最具身份性的数据，两条继承规则承载它们：

- **绝不记录内容。** 日志行携带计数与 id，绝不携带姓名、地址、电话
  号码或组织。通讯录 id 不是内容，可以记录；其中的卡片不行。
- **没有新东西被发往任何地方。** 联系人只与用户自己配置的账户双向
  同步，别无他处；关于它们的任何东西都不进入其他载荷。

## 今日交付

| 表面 | 交付 |
|---|---|
| 桌面 | Mail 与 Calendar 旁的 People 视图：带徽标与 In N accounts 披露的分节列表、带 Also in 与逐值来源的详情、带卡片选择与条件入口的编辑器、带药丸的编写器自动补全、经照片命令的头像 |

实测证明：门控的 harness 套件对点名两源的 dav 节运行真实的
`connect_dav_providers` 及其上的启动形态组装（追加的日历腿、安装的
联系人腿），经原始 CardDAV 面向每个账户的默认通讯录播种卡片，再经
产品自己的同步与快照读回：折叠顺序、分节字母、徽标、说着 In 2
accounts 的那一个合并行，以及点名两个来源的详情。第二个套件往返写
入：对可写通讯录的创建与对点名卡片的改名，各自从服务器读回，每个
写入状态落定。第三个套件经引擎发送路径提交一封新邮件，并断言自动
补全对本次运行自己挖掘的历史的排序。每张播种的卡片与每封发送的邮
件最后都被撤回，harness 保持邮件套件钉定的形状。

## 已知缺口

- **联系人不能删除。** 引擎携带该动词；产品不提供它，因为删除是用
  户无法撤销的唯一联系人写入，它要属于自己的确认与点名账户的步
  骤，按日历删除已有的条件。实测证明用原始播种助手撤回播种的卡
  片，如实标注为播种侧清理。
- **离线写入不持久。** 失败的联系人写入保持失败而不排队：与日历写
  入相同的缺口，记录在那里。
- **同事目录需要 OAuth 账户腿。** Microsoft 或 Google 目录是引擎可
  读的联系人源，但 Astra Mail 尚未拨号任何 OAuth 账户，所以今天没
  有目录站在人员索引之后。
- **JMAP 联系人未实测。** 引擎的 JMAP 联系人适配器存在；没有 Astra
  表面或实测证明锻炼它，所以 CardDAV 腿是唯一被证明的路径。
- **向导没有 dav 字段。** 存储账户的 `[dav]` 节在启动时加载并拨号，
  但还没有表面写它；字段随设置切片落地。
- **照片每次挂载重读。** 头像命令每次调用都从缓存文件构造 data
  URI，web 服务按地址按会话只询问一次（`avatars.md` 拥有的按地址缓
  存），所以一屏带照片的人按地址按会话仍各花费一次文件读取；批量解
  析是后续条目。
- **列表上限 200 人**，没有分页表面：搜索在引擎内收窄，所以超限的
  人找得到，但滚动不到。
