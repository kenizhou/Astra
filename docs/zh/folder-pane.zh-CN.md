# 文件夹窗格：Astra Mail 契约

**范围。** 邮件列表旁的文件夹窗格：它绘制的树、行上的角色与徽标、
头部的统一行、选择与展开、菜单提供的编辑动词、以及它接受的拖放。
对每一个交付文件夹窗格的表面都有约束力。实质移植自 mail-calendar
的文件夹契约，按 Astra Mail 今日交付的范围裁剪；缺口在文末记录，
绝不静默。

**原则。** *窗格按服务器持有的状态绘制账户的树。* 每次编辑都经过
引擎的发件箱，窗格在调和后的树上重绘，所以窗格绝不持有可能与存储
不一致的自有树。

## 树

每个已配置的账户作为一个分组行，标签为其地址（或其所有者发件时所
用的名字），文件夹列于其下。文件夹的行携带它自己的名字，绝不是路
径；缩进表明它所处的位置。遍历为深度优先，带角色的文件夹按固定
规范顺序领先（收件箱、草稿、已发送、归档、垃圾、回收站），随后是
所有按名字排列的自定义文件夹。带角色的文件夹无论服务提供方如何
归档，都绘制在其账户的顶部，所以 Gmail 的已发送绝不藏进
`[Gmail]`。行以扁平方式跨越快照，每个账户一份列表，携带表面选择、
展开或编辑所需的键。

## 角色与徽标

文件夹的角色来自服务器自己的 SPECIAL-USE 标志（RFC 6154），从 JMAP
的等价物镜像而来；窗格绝不从名字猜测角色。未读徽标是服务器自己的
计数，因此覆盖比同步窗口更早的邮件，并与其他客户端显示的一致。零
不绘制徽标。

## 统一行

窗格的头行 `Unified inbox` 将每个账户的收件箱合并为一个列表。只有
窗格持有至少两个账户时它才渲染；单账户不需要看到其收件箱的第二种
方式。点击它选择全收件箱范围：列表按最新在前显示每个账户的收件箱
行，仅限收件箱，每行绑定自己的账户，因此选择与操作无需改变。徽标
求和各收件箱的未读数。该选择跨启动持久：范围随持久化的 UI 状态
走，重新启动会重新打开统一列表。搜索保持自己的范围；统一列表就是
列表，不是搜索。

## 选择与展开

选择一个文件夹显示其邮件；选择一个账户显示该账户的整个邮箱。展开
刻意不是导航：打开或收起一棵树（账户的或文件夹的）既不改变选择也
不改变其他树，核心按账户和文件夹持久化该选择，因此重启重新打开
同一棵树。

## 编辑动词

每一次树编辑都是一条文件夹意图，落在引擎的发件箱式邮箱写入上，
因此离线排队的编辑会在服务器返回时落地，被拒绝的重放以引擎答复
的冲突呈现：

- **创建。** 菜单的 `New Subfolder` 在该文件夹下打开内联行；Enter
  提交，Escape 与失焦取消，空名字绝不提交。
- **重命名。** 菜单的 `Rename Folder` 在该文件夹上打开内联行；特殊
  文件夹附带原因拒绝。
- **删除。** 在回收站之外这是可恢复的动词：文件夹、其子文件夹及其
  邮件移入回收站，前有确认。在回收站之内，菜单改为提供永久删除，
  前有其自己的确认。回收站之外的特殊文件夹绝不删除。
- **Mark All as Read** 在列表正显示该文件夹时，循环其列出的未读行。

重命名或移动会把选择重新落到引擎回执为该文件夹铸造的键上：IMAP
重命名给文件夹新的键，留在旧键上的选择会指向树不再持有的文件夹。

动词按能力门控，绝不以禁用状态出现：其服务提供方无法写树的账户
根本不显示编辑动词，因此没有任何东西提供该账户无法应用的更改。

## 拖放

树的拖放只携带键；邮件内容绝不随拖放走。

- 文件夹落在自己账户的另一个文件夹上会重新挂靠（Move 动词）。后代
  守卫在任何调度之前拒绝落入自己子树的拖放，因此树绝不会落到自己
  内部。
- 文件夹落在其账户行上会成为根。
- 邮件选择落在文件夹上会以一个批次移动这些行，与行菜单选择器分发
  的移动意图相同。拖放在键旁携带其形状，因此悬停会拒绝受保护拖放
  存储所隐藏的内容：会话行拒绝整个拖放，因为移动批次只能命名邮件。
- 跨账户拖放与统一行拒绝；合法目标悬停时高亮，非法目标不高亮。

## 已知缺口

- **IMAP 没有移动，只有重命名**：重新挂靠以整条路径的重命名落地，
  回执铸造键的重新选择就是契约。
- **会话无法移动**：动词附带原因禁用，持有会话行的拖放拒绝落下。
- **排队的文件夹编辑不显示待定标记**：窗格绘制存储持有的树，被拒绝
  的重放以引擎的冲突呈现。
- **文件夹意图携带裸字符串形式的文件夹键**，与其 `AccountId` 并列，
  沿用创建意图确立的形状；到处使用版本化的 `FolderRef` 是以后的
  线上决策。
