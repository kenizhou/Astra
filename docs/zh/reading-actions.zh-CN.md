# 阅读操作：Astra Mail 契约

**范围。** 阅读窗格对收到的邮件的操作：Save As、Download All、
Save as .eml、打印、窗格显示的类型化结果、日志契约、以及把邀请自身
部件挡在附件列表之外的 `.ics` 规则。对每一个交付阅读窗格的表面都有
约束力。实质移植自 mail-calendar 的附件契约，按 Astra Mail 今日交付
的范围裁剪；缺口在文末记录，绝不静默。

**原则。** *字节与引擎同在，直到保存命名它们。* 窗格只列出元数据；
读取发生在保存时，经核心，走引擎缓存优先的抓取。整封邮件也没有
不同：`.eml` 是引擎自己的源读取，绝不是重新序列化。

## Save As

一行，一条命令链：应用核心经引擎读取该部件的解码字节，宿主询问其
平台保存对话框放到哪里（以该行的文件名为建议），写入文件，并答复
类型化结果。**Download All** 在每一行上循环同一条链；结果行回答最后
报告的行。

## Save as .eml

溢出菜单的 Save as .eml 写入引擎的 `message_source` 字节：发件人
服务器投递的原始 RFC 5322 源，与引擎持有的一模一样。重新序列化会
改变信头的措辞、部件的顺序与传输编码，因此不运行任何序列化：折行
的信头保持折行，quoted-printable 正文保持编码，服务器自己前置的
信头一并随行。

建议的名字从主题推导：文件名不能携带的每个字符（路径分隔符、
Windows 禁止的字符、控制字符）折叠为空格，空白串合并为一个，词干
去除尾部的点与空格并截断在八十个字符，`.eml` 后缀落定。净化后为空
的主题、完全没有主题、或词干是 Windows 保留设备名（`CON`、`NUL`、
COM 与 LPT 端口，其加点形式写入会被拒绝）的主题，建议
`message.eml`。

该命令经与附件保存相同的保存对话框接缝，答复附件保存所答复的同一
类型化结果族：保存的路径、读者自己的取消、或拒绝的句子。

## 打印

溢出菜单的 Print 打开一个针对打印优化的窗口，展示当前打开的邮件
并自行打印：`window.print()`，即 webview 打开的平台对话框。Tauri
2.12 存在宿主打印动词，但在 Windows 上它就是由宿主求值的
`window.print()`，包装的 JS API 一个也不暴露，因此把打印留在 web
不增加任何权限。

该文档逐字复用消毒后的阅读视图，绝不是第二个消毒器：主题、信头
行（发件人姓名、地址与日期）、处于当前缩放档位的正文、以及作为
名字列出的附件。正文乘坐阅读窗格自己的乐器，即覆盖消毒片段的
沙箱框架，配以门控内容策略，因此发件人的样式得以渲染，而任何
脚本与任何远程加载都绝不跨越打印。

窗口在文档就绪后打印一次，对话框落定（`afterprint`）后关闭；
完全没有对话框出现时，Escape 关闭它。

## 类型化结果

命令的答复是三种形状之一，绝不是被拒绝的调用：

- **Saved**：字节落到读者选择的路径；窗格显示该路径。
- **Cancelled**：读者未选择即关闭了对话框；没有写入，也没有显示。
- **Failed**：拒绝自己的句子（读取的或写入的），可在窗格中直接
  显示。

## 日志契约

除读者选择的路径之外，关于读取的任何东西都不写入日志：账户、邮件
键与建议的名字都远离每一行日志。

## `.ics` 规则

被邀请表面认领的邮件会从附件行中去除其日历部件：卡片渲染会议，
因此它所来自的 `.ics` 也不再是可下载的文件。普通邮件携带的日历
文件保留其行。

隐藏规则按媒体类型判别，因为没有部件身份跨过引擎的调度读取：
`text/calendar`（iMIP 类型）与 `application/ics`（某些发件人附加的
双保险副本）在被认领的邀请上都隐藏。由此而来的角落已记录而非隐藏：
携带第二个真正附加的日历文件的邀请也会失去该标签，部件身份判别是
以后的引擎表面。

## 已知缺口

- **没有应用内预览**：Preview 项作为占位符站立，打开附件意味着经
  宿主 shell 打开已保存的路径；本切片不携带任何预览。
- **打印的是消毒后的阅读视图**，绝不是原始源；不提供打印原件。
