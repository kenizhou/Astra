# 稍后处理：Astra Mail 契约

**范围。** 将一条邮件搁置到某个唤醒时刻：选一个时间，邮件移入
Snooze 文件夹，到唤醒时刻它返回原文件夹。对每一个交付该动词的
表面都有约束力。引擎没有稍后处理或定时机制，因此这是一个宿主/
核心特性：一个设备本地的稍后处理存储、一个宿主唤醒定时器、以及
既有邮件写入路径之上的两次移动。不改引擎。缺口在文末记录，绝不
静默。

**原则。** *稳定身份是 Message-ID，绝非提供商标键。* IMAP 移动会
在目标文件夹合成一个新的提供商标键，因此稍后处理时存入的键在移出
后即失效。唤醒在一次同步之后按 RFC 5322 `Message-ID` 头重新解析
邮件；它绝不复用存入的键。

## 存储

新 crate `astra-snooze` 持有调度（AI 账本存储的形状：一个 mutex
下的 rusqlite 连接、在事务中认领的嵌入式迁移、五秒忙超时、供测试
的内存打开）。宿主在数据目录打开 `snooze.sqlite` 并安装到核心
（analytics 的安装形状，一个 `Mutex<Option<Arc<Store>>>` 槽位；没有
`AppState` 字段，因此析构顺序保持原样）。每条被稍后处理的邮件一行：

- `account_id`，所属账户（新类型 `AccountId`）。
- `message_id`，RFC 5322 `Message-ID` 头（新类型 `MessageIdHeader`），
  唤醒据此重新解析的稳定身份。
- `provider_key`，稍后处理时的键，仅作诊断：它在移动后失效，绝不
  作为移回目标。
- `wake_at`，唤醒时刻，unix 秒。
- `origin_folder`，邮件返回的文件夹键。
- `subject` 与 `sender`，Message-ID 之外重新解析的回退。
- `created_at`，存储自身的时间戳；`wake_at` 上的索引。

方法为 `record`、`due(now)`（`wake_at <= now`，最早优先）、`remove`、
以及 `list`（供未来的 Snoozed 视图）。身份无法解析的行被跳过，绝不
使读取它的批次致命。存储是设备本地的：它不跨设备漫游，CLI 也不
共享它（一个宿主定时器特性）。

## 核心稍后处理与唤醒

`snooze_message(row, wake_at)` 拒绝会话行（移动只命名消息），确保
账户的 Snooze 文件夹存在，从存储自身的副本读取邮件的 `Message-ID`
与原文件夹，记录条目，然后派发 `MoveMessages` 进入 Snooze 文件夹。
没有 `Message-ID` 的邮件被拒绝：稳定身份正是唤醒所需。

`wake_due_snoozes(now)` 读取到期条目，对每一条同步账户使移动后的
副本对账，在 Snooze 文件夹内按 `Message-ID` 重新解析邮件（主题与
发件人作回退），派发 `MoveMessages` 返回原文件夹（原文件夹不在时
返回 Inbox），并移除条目。不再解析到的邮件或文件夹是陈旧条目：
它被移除而不移动，绝不使批次搁浅。移动重新发布
`Surface::MailboxList`，因此 web 通过既有的 `surface_changed` 循环
得知唤醒；不交付新事件。

## Snooze 文件夹

没有 Snooze `MailboxRole`。稍后处理在缺失时按账户创建一个名为
"Snooze" 的文件夹（`FolderIntent::Create`），并按约定名称（叶子，
忽略大小写）解析其键。该文件夹可经面板到达；专门的 Snoozed 视图
是后续。

## 唤醒定时器

宿主 `snooze_timer`（日历定时器的形状）每分钟滴答一次，读取存储的
到期条目，并通过 `AppPort` 调用唤醒体。它在存储之上无状态，因此
重启会重新读取到期条目。间隔与滴答上限可调试覆盖
（`ASTRA_SNOOZE_SECONDS`、`ASTRA_SNOOZE_LIMIT`）以供确定性运行；
发布构建保持固定节奏且永不停止。定时器持有两个 `Arc`（核心与
存储），因此 `AppState` 的析构顺序不受影响。

## 表面

行菜单的 "Snooze…" 条目（单条消息；会话或批量以原因禁用）打开一个
选择器，提供今天晚些、明天、下周作为计算出的时刻。选其一触发宿主
的 `snooze_message` 命令并关闭；取消与 Escape 不派发任何东西。意图
构造器与 wire 类型位于 `services/snooze.ts`（绝不 `ipc.ts`，已到
上限）；桌面命令位于 `commands/snooze.rs` 子模块（`commands.rs` 已
到上限）。

## 关闭应用时的唤醒精度

定时器仅在进程存活时运行。应用关闭期间到期的唤醒在下次启动时
触发，而非精确时刻：这是桌面宿主定时器的固有特性，记录而非隐藏。

## 已知缺口

- **设备本地**：稍后处理存储不跨设备漫游。
- **关闭应用时的唤醒精度**：关闭应用期间到期的唤醒在下次启动时
  触发，而非精确时刻。
- **自定义唤醒时间**是紧接的后续（原生 datetime-local 复用已存在）。
- **专门的 Snoozed 视图/过滤**是后续（Snooze 文件夹可经面板到达）。
- **会话稍后处理、重新稍后处理/撤销、以及 CLI/agent 稍后处理动词**
  是后续。
- **没有 Message-ID 的邮件**无法被稍后处理：稳定身份正是唤醒重新
  解析的依据。
