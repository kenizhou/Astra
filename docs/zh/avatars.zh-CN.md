# 头像：Astra Mail 契约

**范围。** 每个表面共享的那一个头像：字母头像、照片、缓存，以及一
个头像的代价。对每一个绘制人员的表面都有约束力。字母头像的推导与照
片路径归 `contacts.md` 所有；本文拥有头像立于何处以及它的代价。

**原则。** *一次推导、一条命令、绝不阻塞。* 核心只推导一次每个字母
头像，照片只经过经过校验的缓存照片命令越过，任何表面绝不为了渲染
自己已持有的内容而等待一张照片。

## 字母头像

字母头像即核心的那一次推导（其规则归 `contacts.md` 所有：取此人最
佳姓名的首尾两词首字符，落在按地址键控的调色板颜色上）。表面绝不自
行推导首字符或颜色，因此同一个人不会在一个屏幕上读作 `AL`、在另一
个屏幕上读作 `Ada`。没有可绘制的首字符时，圆圈绘制人形符号。

## 照片

通讯录照片在存在时替换字母头像。照片从引擎的缓存联系人照片库读
出，经过宿主的经校验照片命令，该命令只为引擎自己的联系人照片区域
内的路径提供 data URI：web 视图绝不读取文件系统，任何照片路径都不
作为 URL 越过，浏览器无法被指向别处。照片落地之前字母头像一直站
立；行、头部或列表绝不因这次读取而阻塞，不可解析的读取让字母头像
继续站立。今日没有随产品交付的填充遍：引擎提供填充动词、证明驱动
它，但产品不调度任何照片遍，所以在填充遍交付之前，大多数行显示的
是字母头像。

缓存的信任边界是引擎的。提供商回答“无照片”的资源，一周内不再询
问（地址簿之外的人哪里都没有照片，每轮对每个陌生人重探要按陌生人
各花一次请求）；名片上没有任何能察觉照片变化之物（无媒体指纹、无
修订令牌）的照片，信任三天后重新拉取；携带指纹或修订的名片让自己
的照片失效，所以重新拉取只在可能学到新东西时发生。内联照片（vCard
自带的 `PHOTO;ENCODING=b` 字节，存为 data URI）自成修订：字节即图
片。

## 缓存

每个地址每次会话只询问一次：web 服务按地址持有已解析的视图（字母
头像与照片路径），因此重新挂载的面板从内存重绘，而不是再次越过通
信线。被拒绝的询问被丢弃而不是缓存，因此之后的挂载会重试。

## 列立于何处

- **邮件列表行**在前缘绘制发件人的头像，按地址经缓存解析。该列在
  紧凑密度下隐藏（行自身的密度规则），因为 44 像素的行用文字换掉
  了圆圈。
- **People 视图**与**编写器的建议**从各自的快照行和同一条命令绘制
  头像。
- **阅读表面**（阅读头部）只凭地址经同一条命令解析。

## 代价说明

照片按地址按会话重新读取：缓存文件的字节以新的 data URI 随命令的
回答逐次越过，因此一屏带照片的发件人按地址按会话各花费一次文件读
取。批量解析（一次询问一屏地址）是本说明记录的后续条目。

## 已知缺口

- **无批量解析。** 每个地址各自询问；一屏带照片的发件人按地址各花
  费一次文件读取。
- **无头像编辑。** 上传或裁剪照片是本切片不携带的联系人写入。
