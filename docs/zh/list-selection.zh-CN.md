# 列表选择：Astra Mail 契约

**范围。** 邮件列表如何选择行并对整批操作：选择模型、批量工具栏、
批次循环、移入文件夹选择器、以及 Delete 的诚实含义。对每一个交付
邮件列表的表面都有约束力。实质移植自 mail-calendar 与 kylins 的
选择契约，按 Astra Mail 今日交付的范围裁剪；缺口在文末记录，绝不
静默。

**原则。** *选择是核心已经知道的一组行键。* 表面不持有行的副本，
每个操作都通过与单行菜单相同的意图命名完整的行。

## 选择模型

渲染列表之上的 Outlook 语义：

- **Ctrl** 将一行切入或切出选择；锚点跟随加入的行。
- **Shift** 从锚点到点击的行在渲染项上取范围，方向不限。日期头
  永远不计入：范围只在行上运行。
- **Ctrl+A** 选取每个已加载的行。
- 在选择之内的右击将其保留为操作的目标；在选择之外的右击将选择
  收拢为被点击的行。

锚点是上一次加性手势落到的行；移除锚定行的切换会把锚点移到剩余
的行上。

## 批量工具栏

只要选择成立，列表就升起自己的工具栏：计数、Select All、Clear 与
各操作，因此整批操作不依赖上下文菜单。这些操作与行菜单循环的
相同：已读与未读、标记、归档、以及 Delete（即移入回收站；见下）。
Select All 与 Ctrl+A 选取已加载的行：列表是窗口化的，窗口随列表
滚动而增长。

## 批次循环

一个批量操作按行逐条分发意图，发后即忘；快照带回结果。每次编辑
都经引擎的发件箱，因此存储立即显示更改，服务器在可以时接收；
拒绝以重发布列表中未变的行落地，绝不静默成功。

## 移入文件夹

行菜单的 `Move to folder` 将账户的其他文件夹作为浮层提供；一次
选择以一个批次移动整个目标集，每行一次移动编辑，经发件箱。该
选择器遵守移动自身的约束：

- **单一账户。** 移动保持在行自己的账户之内；跨账户的选择隐藏
  该项。
- **不含会话。** 会话行附带原因禁用该项，因为移动批次只能命名
  邮件。
- **不提供当前文件夹。** 移到行已在的文件夹上是空操作，应用不做
  任何排队即予答复。

## 回收站与删除的诚实性

文件夹之内的 Delete 是移入回收站：行落入账户的回收站，可从那里
恢复。永久删除是行菜单自己的条目，菜单在哪里打开它就站在哪里：
危险样式、位于普通 Delete 之下、前有其自己的确认，且绝不进入
批量循环（一次一行；多选时它带原因禁用）。回收站的批量删除保持
自己的表面。永久删除无可恢复；引擎的动词不可逆。批量工具栏的
Delete 遵循与行菜单相同的规则。

## 悬停动作

邮件行尾缘携带悬停时显现的快捷动作：归档、删除（移入回收站）、加旗、
标为已读/未读。各仅作用于被悬停的行，绝非多选（批量工具栏与行菜单拥有
批量），且按钮点击绝不选中或打开该行。槽位也在选中与 focus-within 时
显现，使已选中某行的键盘用户能 Tab 进入按钮；行本身保持不可聚焦，
ribbon、面板与行菜单仍是主要键盘路径。草稿行抑制邮件动作（草稿菜单的
动词是打开与删除草稿）。加旗行无需悬停即保持其加旗按钮可见。悬停槽位
不提供撤销，与行菜单和 ribbon 一致；滑动拥有撤销。触摸用户（无悬停）
保留滑动、行菜单与批量工具栏。

## 清扫

行菜单的「Clean up sender」条目打开一个对话框，清扫当前文件夹中一个
发件人的邮件。它按发件人地址过滤已加载行（列表过滤自己的谓词），以
「在此文件夹中」预览计数，并诚实注明仅计数已加载行，还展示匹配主题的
一个有界预览。动作为归档（默认）或移入回收站；确认在匹配行上循环所选
intent，即批量工具栏自己的批量模式，然后关闭。取消与 Escape 关闭而不
派发；空匹配带原因禁用确认。动作止于行的回收站（无永久删除），且无
撤销，与批量工具栏和行菜单一致：确认是守卫。v1 仅清扫当前文件夹的已
加载窗口；搜索 intent 之上的跨文件夹清扫是命名的后续。

## 快捷步骤

快捷步骤是用户定义的宏，一键在所选行上运行一个邮件动作。一个步骤是一个
名字、一个动作（归档、回收站、标已读、标未读、加旗、去旗，或移入一个
具体文件夹），以及一个可选的先标已读修饰；至多五个按设备本地保存
（localStorage）。ribbon 为每个步骤携带一个按钮（无选择时禁用）与一个
打开编辑器的 Manage 按钮。运行器把动作映射到既有 intent 并在选择上循环
它（批量选择，否则单锚点）；先标已读先运行，因为被归档的行离开快照。
move 跳过会话行与外账户行并带一个计数 toast（移动批次无法命名一个会话，
且一个具体文件夹属于一个账户）。归档动词止于回收站且无撤销，与批量
工具栏一致。snooze、键盘槽位、role 目标与多段序列是命名的后续。

## 置顶

置顶行浮到列表顶部。置顶集是设备本地的（localStorage），按行身份
（账户与键）键控，故置顶按账户作用域，且消息置顶与会话置顶不同。一个
纯稳定分区把置顶行浮到最前，在每个分区内保留引擎顺序（无日期重排）；
它仅作用于文件夹与统一列表，在过滤之后、日期头之前，保持快照、引擎
顺序、基于键的选择与 ShowMore 不动。搜索结果保持自己的顺序。行菜单
携带一个置顶 / 取消置顶开关（可批量、幂等），置顶行展示一个持久的置顶
指示器。置顶仅在已加载窗口内浮动；超出可见上限的置顶在 ShowMore 加载
它后出现。扁平消息置顶与线程会话置顶之间的跨模式映射需要扁平行上的
线程 id（引擎工作），一个命名的后续；尚无「已置顶」过滤标签页。

## VIP 发件人

VIP 发件人是用户标记为重要的发件人：其行佩戴一个小星形徽章，过滤新增
一个 VIP 标签页，只答他们的邮件。VIP 集是设备本地的（localStorage），
按发件人的裸地址键控（小写并去空白，显示形式提升为 addr-spec），故标记
属于发件人本人、跨账户成立，与置顶集的逐账户行键不同。行菜单携带一个
添加 VIP / 移除 VIP 开关（可批量、幂等），即置顶开关自己的形状：标签随
目标发件人的状态翻转，批量落地一个状态。空白发件人地址被拒绝。过滤保持
客户端侧、作用于已加载行，绝不是一个 intent：VIP 标签页答发件人在集中的
行，标签页的计数在列表渲染的单一收口处读同一个集，即置顶模式。徽章与
过滤只读已加载行：没有已加载行的 VIP 发件人，在其邮件加载前什么都不显示。
该集按浏览器配置文件作用域，无跨设备同步；VIP 邮件的通知或优先路由是
命名的后续。本切片是标记、徽章与过滤。

## 稍后处理

行菜单的 "Snooze…" 条目将一条消息搁置到某个唤醒时刻：它打开一个
选择器，提供今天晚些、明天、下周作为计算出的时刻，选其一将消息移入
账户的 Snooze 文件夹并把调度记录在设备本地。到唤醒时刻，宿主定时器
将消息返回其原文件夹。会话或批量附带原因禁用（移动只命名消息）。
稳定身份是消息的 `Message-ID`，绝非移动重新合成的提供商标键；完整
契约、存储与关闭应用时的唤醒精度见 [snooze.md](snooze.md)。

## 已知缺口

- **会话无法移动**；动词附带原因禁用。
- **Select All 选取已加载的窗口**，而不是文件夹的全部内容；列表
  是窗口化的，窗口只随列表滚动而增长。
- **没有撤销**：批量操作经发件箱落地，回去的路是回收站，不是
  按键。
