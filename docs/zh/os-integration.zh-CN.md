# 操作系统集成：Astra Mail 契约

**范围。** Astra Mail 与操作系统相遇的三条腿：默认邮件应用提议、
主窗口记住的几何形状、以及交接进新消息的分享。对桌面宿主有约束力。
托盘与自启动保持缺席；没有行点名它们。

**原则。** *询问操作系统，绝不抓取。* 每次注册都是明确的接受，每个
记住的形状要么被下次启动如实恢复、要么被如实丢弃，操作系统交给
进程的一切都在门口过滤后才触及邮件。

## 默认邮件应用提议

Astra Mail 提议成为操作系统的默认邮件应用，只提议一次，且设置中
可改。

- **只问一次。** 问一次的闩在宿主侧，是应用数据目录里的
  `default-mail-asked` 文件，因为接受是一次宿主拥有的操作系统注册，
  核心的设置块没有别的用途。提议的两个答案都会花费它：接受即
  注册，放过即收下横幅。提议只在有账户站立时出现（没有账户，
  无可提议）；闩的读取被拒也绝不纠缠：读不了的闩按已问计。
- **设置中的更改。** General 页的 *Make Astra Mail the default
  mail app* 行，经提议接受所用的同一动词重新断言注册，因此默认
  在提问之后仍可更改。动词幂等且诚实：已站立的注册应答
  `already_default` 而不触碰操作系统，因为人可能在此期间把默认
  指向别的应用，只有其本人的请求才移动它；拒绝以自己的句子应答，
  随时可展示。
- **注册本身。** 接受经深链插件运行时注册认领 `mailto` 关联，与
  安装版构建的清单静态声明的是同一注册。交接确实生效的操作系统
  级证明（操作系统真的递来一个 mailto 链接）等待安装版构建，与
  mailto 行已记录的等待完全一致。

## 窗口状态

主窗口跨启动记住尺寸、位置与最大化，在应用数据目录上手写实现
（`window-state.json`，无插件），因为窗口状态文件不是偏好：核心的
偏好文档保持它是的那一份文档。

- **尺寸与位置在创建时应用。** setup 钩子在 shell 创建窗口之后、
  事件循环首帧之前应用持久几何，因此绝不闪现错误尺寸的框。
- **最大化状态在框显示之后应用。** 页面首次完成加载之时，因为
  框显示前最大化窗口会砸掉还原下的几何（这个 one-shot 就是为
  避免那次闪烁而存在）。
- **显示器交集。** 保存于已不存在显示器（笔记本离开坞站）的位置
  会让框开在不可见处：保存的矩形必须与一个站立的显示器相交，
  否则以配置默认值站立。读取不了的显示器列表按相交计，因为
  读取被拒就拒绝恢复，会搁浅一个可能完全没问题的保存状态。
- **回退。** 缺失、不可读、不可解析或不合常理的文件回退到配置
  默认值（窗口配置声明的固定 1200 乘 800），首次启动也站在同一
  默认。没人能造出的窗口尺寸是损坏文件，不是可恢复的状态。
- **还原下的局限。** 操作系统的还原下矩形无法经 shell 的 API
  读取，因此最大化关闭保存的是最大化框自己的几何：最大化关闭的
  窗口恢复为最大化，随后的取消最大化站在最大化框的尺寸上。这是
  手写状态的点名代价，宁可如此也不做几何猜测。

关闭时尽力保存：无法序列化或持久化的几何只打日志，绝不让请求
保存的关闭失败。

## 分享交接

操作系统或人交给进程的文件，经一个事件交接进编写预填，是 mailto
通道的姊妹件。

- **Windows 判定。** 操作系统分享契约（打包应用作为目标注册的
  Share UI）需要包身份，而桌面构建是非打包 Win32 应用，因此没有
  运行时注册能让它成为分享目标。诚实交付的交接是文件关联的
  “打开方式”道路：文件参数在启动时到达进程，或在应用已运行时经
  单实例守卫到达，与 mailto 链接走的正是同一条 argv 道路。
- **门。** 一切在越过之前被过滤：只有带普通名字的既存普通文件
  幸存。目录、什么都不指的路径、不普通的名字（空、路径自行解析的
  两个名字、任何控制字符）被丢弃；操作系统双击会执行的每种类型
  同样被丢弃，包括原生安装会关联的脚本宿主（`exe`、`bat`、`cmd`、
  `com`、`scr`、`msi`、`ps1`、`vbs`、`js`、`jse`、`vbe`、`wsf`、
  `wsh`、`hta`、`lnk`、`pif`、`scf`、`cpl`、`reg`、`jar`）：
  经分享寄出的可执行文件或脚本是经典的钓鱼形状。
- **待定行体验。** 幸存者在分享通道上越过，编写器打开一个带预填
  的新消息，每个文件一行待定行。行显示文件自己的名字；路径随
  组合被持有，绝不渲染。
- **字节装载余项。** 没有读取缝交付：webview 没有自己的文件系统，
  待定行站在那里而字节未装载，因此有行站立时发送如实拒绝，而不
  是寄出一个承诺。
- **打包分享目标余项。** 注册为真正的操作系统分享目标需要打包
  构建；该行把它作为点名等待携带。

## 已知缺口

- 默认邮件注册的操作系统级证明等待安装版构建（mailto 行的既有
  等待）。
- 分享目标是“打开方式”道路，不是操作系统 Share UI；打包构建是
  等待。
- 分享文件不装载字节：待定行点名文件，有行站立时发送拒绝。
- 最大化关闭的还原下几何是最大化框自己的，即上文的点名代价。
