# 展示模式：Astra Mail 契约

**范围。** 启动由夹具支撑的外壳以供商店截图的调试旗标：一个环境
变量选定一个录制的屏幕，桌面宿主以录制的快照作答而不拨号任何东西，
生产 webview 包原样运行。仅限调试构建；缺口在文末记录，绝不静默。

**原则。** *交付的二进制不可能被换掉表面。* 整条展示路径只在调试
构建中编译，因此发行构建的任何环境变量都无法用录制的答案顶替真实
账户。

## 旗标

`ASTRA_SHOWCASE` 指名本次运行要拍摄的那一块屏幕：`list`、
`reading`、`settings` 或 `people`，按字面匹配（折叠大小写、修剪两侧
空白）。未设置，或为关词之一（`0`、`false`、`no`、`off`、空），
即生产启动。未知名称被拒绝并在错误中带出该名称，而不是静默地拍成
列表：把错误的屏幕拍得再亮，也是下游什么都察觉不到的失败。

## 夹具支撑的宿主

旗标立起时，启动组装的是夹具应用而非生产应用：不拨账户、无引擎
存储、无 LLM 客户端。命令层以 web 夹具架携带的录制快照作答，这些
快照从 web 测试已有的夹具编译进来：每个屏幕都有邮箱列表，阅读屏
另带一个处于打开状态的阅读快照，设置屏带设置快照，通讯录屏带
people 快照。生产 webview 包针对这些答案原样运行；把测试架挡在生产
之外的别名规则保持完好。数据目录下展示自用的角落持有账户索引，
且始终为空。

参考客户端的内存提供商启动被记录为未采纳：它需要 vendored 树不
携带的绑定代码，且与先拨号再启动的启动方式相抵，而一次截图运行
不需要真实引擎的保真度。

## 冻结的日期

快照的日期按录制原样站立。没有钉住任何时钟，因此一次运行拍摄的
就是夹具所携带的东西：以冻结录制日近似的一个种子化的今天，而非
活的当下。

## 已知缺口

- **夹具是没有钉住钟面的静态记录。** 日期按录制冻结，因此截图运行
  无法立足于选定的某一天。
- **只有四块屏幕。** 列表、阅读、设置与 people；尚未录制编写器或
  日历屏幕。
