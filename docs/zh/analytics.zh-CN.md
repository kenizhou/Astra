# 经同意的分析：Astra Mail 契约

**范围。** Astra Mail 记录的产品分析：同意机制、载荷规则、仅本地
的汇聚点，以及事件落账的台账。对每一个上报产品事件的宿主部件都有
约束力。没有上报端点交付；缺口在文末记录，绝不静默。

**原则。** *同意就是开关，开关双向各一次点击。* 默认关闭，一次点击
授予，同一开关关闭即撤回。开关关闭时不记录任何东西，撤回在下一次
调用即停止流动，因为闸门在每次调用时实时读取持久偏好，而不是启动
时钉住的状态。

## 同意闸门

记录器住在应用核心里。每次调用都过闸门：

- **无同意，无行，无错误。** 从未立起的同意什么都不记录；调用
  应答为空，绝不让它所在宿主流程失败。
- **同意经设置意图。** 隐私设置分类的开关派发与每个同意动词相同的
  写入；偏好在派发应答之前持久化。
- **撤回是同一写入的关闭。** 一次点击，下一次调用不记录任何东西。
  再次授予则再次记录：闸门读取实时偏好。
- **没有台账安装，什么都不记录。** 没有台账的应用什么都不记，与
  没有账户存储的应用不渲染行是同一形状；台账写入失败只打日志，
  宿主流程继续走。

## 载荷规则

只有计数与形状，绝无内容。一个事件是来自宿主自有封闭词表的形状
名字，加上命名的整数计数，因此任何主题、地址或正文都装不进一个
值：行形状本身保证了这一点，与工具调用台账的列集合同一规则。
当前交付的形状：`app_open`（启动自身的事件，携带站立账户计数）、
`log_exported`（字节数）、`default_mail_registered`（裸出现）。

## 仅本地的汇聚点

经同意的事件落入应用自己的 AI 台账，与工具调用、LLM 调用台账同一
sqlite 存储（`ai.sqlite`），在自己的 `analytics_events` 表里：每
事件一行，形状、以名字到整数对的 JSON 对象存放的计数，以及存储
自己的创建戳。这些行不关联 correlation id：它们是产品事件，不是
agent 回合。

没有任何东西离开设备。端点不存在，发明端点是所有者的决定而不是
一次移植：汇聚点与上报端点是这一行的点名等待，隐私声明以自有
语调陈述真相（被记录的事件是保存在这台设备上的计数与形状）。

## 已知缺口

- 除本地台账外没有汇聚点，没有上报端点交付：站立的是同意机制、
  无内容载荷与撤回。
- 没有表面回读台账：这些行由所有者自己从 sqlite 文件读取。
