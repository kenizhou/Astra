# 签名：Astra Mail 契约

**范围。** 签名如何撰写、如何分配、如何播种进一封编写中的邮件、
以及如何随 From 选择而交换。对每一个打开编写器或编辑签名的表面
都有约束力。

**原则。** *签名只在设置中撰写一次，绝不再重打。* 编写器播种被
分配的块，并把它当作编写器原样显示的保留内容；一个人就地编辑过
的文字属于他本人，绝不在其脚下被换走。

## 撰写表面

设置拥有这个编辑器：富文本，携带编写器承载的同一组标记（粗体、
斜体、下划线、字号档位、两个颜色标记、链接、列表）。撰写好的块
以两条腿跨越，一段 HTML 片段与其纯文本渲染，并持久化在引擎存储
旁的偏好文档中。

## 分配

每个账户持有两个槽位：新邮件打开时的签名，以及回复与转发打开时
的签名。同一个签名可以同时服务两者，任一槽位也可以在另一个持有
签名时保持为空。账户最后一个变空的槽位会把它的行一并带出偏好
文件，因此文档只持有有效的分配。分配以增补方式挂在设置快照的
账户行上；缺失即表示该账户不播种任何签名。

## 播种

新邮件把新邮件槽位的块播种在文档顶部。回复或转发把回复槽位的块
播种在引文原始内容的正下方，且在任何表面重排引文之前，因此无论
引文样式设置如何搬动引文，签名都留在当事人的文字之下。已经携带
签名的文档不再播种：恢复的草稿或重新打开的编写拥有它已有的那一个。

## 交换

在编写器的 From 选择器中更改账户，会把仍然等于播种基线的签名
换成新账户自己的槽位（按编写的种类：回复或转发取回复槽位，普通
编写取新邮件槽位），新账户不播种任何签名时则将其移除。当事人
编辑过的签名不再等于基线，因此保留：编辑过的签名属于当事人。
没有基线站立时，什么都不交换。

## 发送

发送渲染文档携带的内容：渲染器原样发出该块，纯文本腿携带
RFC 3676 分隔符。发送时不追加任何签名。

## 已记录的缺口，绝不静默

- 内联徽标不随本片交付：签名中的图片需要在播种时绑定附件，
  那是它自己的一次变更。
